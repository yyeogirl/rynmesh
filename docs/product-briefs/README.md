## 依赖关系

- 阅读与配对可分别开发；分享选择器先复用最小收藏列表。
- Ask Ryn 先统一节点端会话，再接入模型切换和内容问答。
- AI 设置复用原生运行时；好友 AI 权限依赖稳定的好友关系和服务端授权。
- 搜索依赖对应内容与会话可用；好友更新依赖配对与内容可见范围；离线阅读依赖正文提取。
- 多设备同步依赖稳定的收藏、阅读进度和节点会话格式，最后开发。

## 通用验收标准

以下适用于全部八项需求；专属用例见各文档。所有验收结果初始均为“未执行”。

| 编号 | 验收项目 | 通过条件 |
|---|---|---|
| G01 | 干净安装 | 全新数据目录，无历史、无模型、无好友时有正确入口和空状态 |
| G02 | 完整流程 | 从实际页面入口完成用户任务，无需手工改配置文件或数据库 |
| G03 | 页面状态 | 加载、空、错误、有内容均有测试；错误提供恢复动作，不无限转圈 |
| G04 | 重启恢复 | 已保存数据仍在，中途操作可恢复或明确失败，不伪造完成 |
| G05 | 重复与并发 | 连点、重试、重复投递不产生重复记录或结算；并发符合各文档规则 |
| G06 | 权限与隐私 | 未授权请求由节点拒绝；私有内容、会话和秘密不进入普通日志、诊断或公开注册信息 |
| G07 | 可访问性 | 主要流程可仅用键盘完成；弹窗焦点正确；状态不只靠颜色表达 |
| G08 | 数据维护 | 新数据纳入明确的导出/擦除范围；秘密不默认导出；升级保留原数据 |
| G09 | 故障隔离 | 搜索、AI、好友或同步失败不使整个应用和已可用阅读一起失效 |
| G10 | 发布证据 | 记录提交、平台、环境、步骤、预期/实际结果、耗时及限制；只声明实测范围 |

## 测试与验收材料

1. 后端验证真实存储、权限、去重和恢复；前端覆盖所有可达状态及交互。
2. 每个功能提供可重复执行的端到端流程；候选版本通过项目规定的测试、检查和构建。
3. 桌面验收使用打包应用，不能只用开发服务器；网络功能使用两个独立节点。
4. 完整好友跨网里程碑需要产品双节点 CI 和不同公网出口实机验收，LAN 结果单独记录。
5. 步骤和结果放入 `docs/acceptance/<feature>/`，feature 使用本目录对应文档名称。
6. 证据仅记录合成案例编号、状态、耗时和安全错误码，不保留正文、模型输入输出、邀请秘密、密钥或个人绝对路径。

每条用例填写：`编号 | 实现提交 | 环境 | 实际结果 | 通过/失败/未执行 | 证据位置`。
必测项未通过或声明平台缺实机证据时，保持“候选/待验收”，不标记全部完成。
