# 06 关注好友的内容更新

状态：需求草案，待开发与验收。优先级：后续优先，依赖好友关系与内容分享。

## 1. 目标与流程

用户主动订阅好友愿意分享的新内容，不需要朋友每篇都单独发送；发布者始终能看清分享给谁。

发布者：选择内容 → 选择可见范围 → 预览并发布 → 查看/调整受众 → 可停止分享。

接收者：打开好友页 → 关注 → 查看好友更新 → 打开阅读/收藏 → 可取消关注。

## 2. 功能需求

| 功能 | 具体规则 |
|---|---|
| 关注 | 仅有效好友可关注，用户主动开启；成为好友不自动关注 |
| 发布 | 收藏、阅读、聊天不会自动变成发布；用户明确选择内容和分享范围 |
| 指定好友 | 仅选择的好友有权读取；后续新增好友不自动加入此范围 |
| 全部好友 | 明确提示包含当前及以后建立的有效好友；默认仅指定好友，首次使用全部好友需明确选择 |
| 受众检查 | 每条发布展示范围及当前有权访问者；“有权限”不等于“已阅读”，不展示虚假的阅读名单 |
| 关注列表 | 按发布时间展示可见内容，显示作者、来源、未读/已读及更新状态；支持手动刷新 |
| 首次关注 | 加载最近仍可见内容，建议首批最多 20 条，支持继续加载 |
| 增量更新 | 前台在线定期检查，离线显示上次更新时间；同一发布按稳定身份去重 |
| 内容修订 | 更新原条目并标注已更新，不重复生成新发布；阅读时说明当前版本 |
| 取消关注 | 停止后续自动收取，移除该作者的关注列表入口；历史私聊、单独收藏和下载副本保留 |
| 停止分享 | 拥有者立即拒绝新的受保护内容获取；接收端获知撤销后隐藏待访问条目并更新状态 |

## 3. 权限与离线规则

- 关注只是接收偏好，不赋予额外内容、AI 或文件权限；权限由发布者节点校验。
- 收窄受众、删除好友或停止分享后，旧链接、旧列表和缓存凭证不能绕过新访问检查。
- 接收端离线时可能暂不知道撤销，不能承诺立即远程删除；界面标记最后同步时间。
- 撤销无法收回接收者此前保存的独立副本，发布与撤销时均需说明。
- 私有正文不写入公开 Registry；仅向当前授权接收者提供必要的列表信息。

## 4. 异常与恢复

无关注时提供好友选择入口；无更新时说明尚无可见内容。
好友离线或网络失败时保留本地状态，显示上次检查及重试，不把离线当作取消关注。
发布失败时保留草稿；只有拥有者确认保存成功才显示已发布，投递/被读取另行区分。

首版不做公开社交广场、评论点赞、推荐算法或自动转发。应用关闭时不承诺实时推送；通知中心可后续接入。

## 5. 验收标准

同时满足 [通用验收标准](README.md#通用验收标准)。

| 编号 | 操作或条件 | 通过条件 |
|---|---|---|
| FOLLOW01 | 建立好友后不关注，再主动关注 | 默认不订阅，主动关注后显示最近可见内容并可分页 |
| FOLLOW02 | A 仅向 B 发布，B/C 均关注 A | B 可见；C 的列表和直接获取均无权读取 |
| FOLLOW03 | 选择全部好友，然后新增好友 D | 选择时已明确含以后好友；D 按范围有权访问，指定好友发布不会自动扩大 |
| FOLLOW04 | 收藏/阅读一条私有内容但不发布 | 好友看不到，也不出现自动发布记录 |
| FOLLOW05 | A 发布，双方前台在线且链路正常 | 建议 60 秒内出现一次；手动刷新可拉取，记录发布到可见耗时 |
| FOLLOW06 | 同一更新重复投递、修订、重启 | 无重复条目，修订显示更新状态，关注与已读状态保持 |
| FOLLOW07 | 取消关注后继续发布 | 不自动收取新内容；已有私聊、独立收藏和下载副本不误删 |
| FOLLOW08 | 收窄受众、删除好友、停止分享 | Provider 立即拒绝新获取；接收端联网刷新后更新可见列表 |
| FOLLOW09 | 撤销时接收端离线 | 有最后同步标记，不承诺远程抹除；重连后执行新权限 |
| FOLLOW10 | 发布失败、好友离线、无更新 | 草稿可恢复，离线可重试，空状态明确，不显示假发布或假已读 |

需提交：至少三个节点/身份的受众验证、更新去重、取消关注及权限收窄记录。
