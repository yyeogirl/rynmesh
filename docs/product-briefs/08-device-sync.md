# 08 自己的多设备同步

状态：需求草案，待开发与验收。优先级：后续，先验证同一用户两台桌面设备。

开发进展：已接入收藏/阅读及会话来源、冲突保留、双端审核和加密批次传输。来源保存后才确认；“我的设备”展示待确认数、确认时间及冲突，支持范围选择、暂停与移除。接收端无模型也能阅读同步会话，收藏与阅读位置可被搜索。“我的阅读”可继续同步文章；阅读器审核冲突及正文版本变化，保存时检查已读取的修订。冲突选择与正文滚动位置均已在本机双节点同步及接收端重启中验证。规模性能、完整擦除及打包跨网验收仍待完成。见[开发验证记录](../acceptance/device-sync-development/README.md)，不代表下列验收通过。

## 1. 目标与流程

用户在电脑 A 收藏、阅读或对话后，到电脑 B 可以继续；离线修改可补齐，冲突不会静默覆盖数据。

已有设备发起配对 → 新设备确认身份 → 选择同步范围 → 首次同步 → 离线使用 → 重连补齐 → 可暂停或移除设备。

## 2. 同步范围

| 数据 | 首版同步内容 | 不随之同步 |
|---|---|---|
| 收藏 | 稳定内容标识、标题、来源、收藏/取消收藏状态 | 下载正文和附件 |
| 阅读进度 | 内容标识、阅读位置、完成状态及必要版本信息 | 未保存的临时页面状态 |
| Ask Ryn 会话 | 会话、消息、原 Provider/服务键、材料引用和最终任务状态 | 模型文件、运行中计算、API 密钥与 Provider 凭证 |

首版不自动同步好友关系与权限、好友私聊、全部文件或系统设置。
同步过来的材料引用不代表新设备已有正文；缺失时明确提示。同步会话不会自动获得远端模型权限。

## 3. 功能需求

- “我的设备”配对与“好友”配对区分；旧设备与新设备均审核确认，邀请一次性且有有效期。
- 新设备显示设备名及可核对的身份信息，确认前不传个人数据；传输加密并验证设备身份。
- 收藏、阅读进度、会话分别勾选，开始前显示方向为双向及涉及的数据类别，不默认静默全选。
- 首次同步合并两端已有数据，不用某一端覆盖另一端；保留稳定身份以去重。
- 展示同步中、已同步、等待连接、暂停、失败、需处理冲突，以及最后成功时间和待处理数量。
- “已同步”只在对端确认所选范围变化后显示；单纯发送请求或进入邮箱不能算完成。
- 离线修改先可靠保存，在设备互相可达时补齐；首版不承诺两台设备永不同时在线也能完成同步。
- 支持暂停/恢复。关闭某类同步只停止后续同步，不抹除已复制的数据。
- 移除设备后拒绝其后续同步与旧凭证，不因重新发现自动恢复；重新加入必须重新配对。

## 4. 冲突与删除规则

不能只靠电脑的墙上时钟判断新旧，应识别设备内操作顺序和两端是否已看到对方变更。

| 场景 | 首版处理规则 |
|---|---|
| 两端收藏同一内容 | 合并一条，保留已有来源；重复消息不重复新增 |
| 一端取消收藏，另一端仍是旧记录 | 取消状态同步过去，旧副本不能自动复活 |
| 明确看过取消状态后重新收藏 | 视为新操作，可以恢复收藏 |
| 两端离线并发收藏/取消同一内容 | 并发时取消优先，界面说明合并结果，用户可再次明确收藏 |
| 先后修改阅读位置 | 采用因果顺序中较新的操作，包括用户主动往前重读 |
| 两端离线并发修改阅读位置 | 保留两个候选位置并提示用户选择；不简单取最大百分比或设备时间 |
| 同一会话两端离线继续提问 | 公共历史去重，两条续聊保留为可识别分支，不把不同上下文答案混成一条时间线 |
| 会话删除与另一端新增消息并发 | 从普通会话列表移除原会话；新增分支进入待处理恢复项，明确提示保留或删除，不静默丢失或复活 |
| 同步双方均确认删除后收到旧消息 | 删除记录阻止复活；旧数据、重试和乱序不能重新创建 |

删除确认框说明是删除下载副本、取消收藏，还是删除同步范围内的会话。普通删除可保留
恢复项；“擦除个人数据”是单独操作，必须包含本地冲突/恢复项。远端离线或被移除时，不能承诺已远程擦除。

待恢复会话提供“保留为独立会话”和“丢弃恢复项”两个操作。丢弃前列出该会话的恢复分支数及本机未发送草稿范围；审核后内容变化则重新审核，原任务未结束时先等待。已独立保留的会话不随之删除。丢弃成功仅表示本机已保存删除决定，对端是否收到以设备确认状态为准；此操作不等同于清理旧浏览器副本、备份或订单结果。

## 5. 异常与恢复

- 对端离线、应用关闭或链路不可达：显示等待连接，本机读写继续可用。
- 同步中断、重启或重复接收：依据检查点继续，已确认变化不重复导入。
- 目标存储不足或写入失败：不确认已同步，保留源数据与待同步状态，可清理后重试。
- 新设备没有原模型/权限：历史可读，发送前显示不可用；不得自动换服务重发历史。
- 移除设备不等于远程删除其旧副本；操作前明确告知，并停止传输新的变化。

## 6. 验收标准

同时满足 [通用验收标准](README.md#通用验收标准)。

| 编号 | 操作或条件 | 通过条件 |
|---|---|---|
| SYNC01 | A/B 首次配对，确认前抓取传输行为 | 未确认不传个人数据；过期/重复邀请不能加入额外设备 |
| SYNC02 | 只选收藏，再分别开启进度与会话 | 仅所选范围同步，未选数据、模型、正文、密钥和好友权限不传 |
| SYNC03 | 两端原有不同数据，首次同步 | 合并不覆盖，重复收藏/消息仅一份，原服务键保留 |
| SYNC04 | 参考双设备、稳定连接、两端各不超过 1 万条元数据记录 | 新增 100 条合成变更，建议 60 秒内完成确认；记录环境与字节数，大规模首次同步单独计时 |
| SYNC05 | 离线修改→中途断开→重启→重连，重复/乱序投递 | 变化补齐，原数据无损，不重复；接收成功前不显示已同步 |
| SYNC06 | 收藏新增/取消并发，随后明确重新收藏 | 按表中规则合并，旧记录不复活，新明确操作可恢复 |
| SYNC07 | 先后及并发修改阅读位置，并让 B 时钟偏差一天 | 先后操作按因果顺序；并发保留选择，时钟差不造成静默覆盖 |
| SYNC08 | 同一会话两端离线继续，另测删除与新增并发 | 分支完整可见；删除冲突进入待处理项，不混入主历史或静默丢弃 |
| SYNC09 | 目标空间不足、写入失败后恢复 | 不错误确认，源记录保留，重试可完成 |
| SYNC10 | 暂停/关闭会话同步，随后恢复 | 暂停期间不继续传相应数据，旧副本保留；恢复后正确补齐 |
| SYNC11 | 移除设备，重放旧凭证并重新发现 | 后续同步拒绝，须重新审核配对；界面说明旧副本无法自动收回 |
| SYNC12 | B 无模型/权限时打开同步的旧会话 | 历史可读；新提问被明确阻止或提示选择，不静默换 Provider |
| SYNC13 | 擦除会话范围，并检查本地恢复项及旧同步消息 | 本地对应数据与恢复项被擦除，旧投递不复活；远端未确认删除明确显示未完成 |

需提交：双设备初始合并、断线恢复、四类冲突、身份撤销与数据范围验证。实际支持的平台组合分别测试。
