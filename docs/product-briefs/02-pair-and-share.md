# 02 两人配对与分享

状态：需求草案，待开发与验收。优先级：第一批，对应 #30。

## 1. 目标与流程

把邀请发给尚未安装 Ryn 的朋友，对方按指引加入并完成第一次分享。好友关系只开启明确的分享能力，不自动开放 AI 或其他服务。

创建邀请 → 复制或扫码 → 对方安装/打开 → 审核身份和授权 → 接受 → 分享 → 确认接收 → 可撤销。

## 2. 功能需求

| 功能 | 具体规则 |
|---|---|
| 创建邀请 | 展示当前可达范围；生成一次性邀请，建议默认 15 分钟有效，可提前取消 |
| 安装指引 | 复制内容包含安装地址、邀请码、有效期和粘贴步骤；二维码本地生成 |
| 邀请审核 | 接受前展示邀请者、节点身份、待访问端点和授权范围；未确认不请求待审核端点 |
| 消费邀请 | 同一邀请最多建立一次关系；同一成功请求重试返回原结果，其他接受者不能再次消费 |
| 分享入口 | 好友页发送文本或小附件；阅读页/已保存列表发送内容卡片 |
| 附件 | 发送前显示大小和当前路径上限，超限阻止；接收方主动保存或打开 |
| 内容卡片 | 显示标题、发布者、来源、获取状态；确认后才获取私有正文 |
| 送达状态 | 区分待发送、发送中、已入邮箱、已送达、失败、过期；已送达需接收端确认 |
| 离线恢复 | 适合大小的消息使用已有加密邮箱；超限附件等待可用传输，不承诺邮箱承载任意文件 |
| 重试 | 保持消息身份，重复投递不生成重复关系、消息或卡片 |
| 撤销 | 本地立即禁止新的好友访问；远端通知可以排队，不能等对方在线才撤销 |

## 3. 异常与恢复

- 过期、取消、已使用分别提示，并可重新索取邀请；安装耗时造成过期也有恢复指引。
- 对方离线或端点不可达显示等待/重试，超时不能显示接受成功。
- 邮箱满、消息过期说明未送达，由用户决定是否再次发送，不无限重试。
- 对方离线时仍可撤销，本地立即拒绝旧凭证，界面区分本地生效与远端待通知。
- 撤销不能删除接收者已保存的副本，撤销确认界面须说明。

## 4. 范围与复用

统一既有候选好友模型，复用 Transport、邮箱和内容分享能力。
首版不授予 AI/VPN、文件系统或 trusted-root 权限，不自动下载私有正文。
粘贴邀请必须完整可用，不依赖深链；LAN 与跨 NAT 分别验收，端口容量按真实限制展示。

## 5. 验收标准

同时满足 [通用验收标准](README.md#通用验收标准)。

| 编号 | 操作或条件 | 通过条件 |
|---|---|---|
| SHARE01 | A 已安装，B 未安装 | B 凭邀请文本完成安装/打开、审核、接受和分享，无需手工改配置 |
| SHARE02 | 粘贴邀请但不确认 | 身份、权限可检查，未向待审核端点请求 |
| SHARE03 | 两个接收者并发接受 | 仅建立一次关系，另一方得到已使用提示 |
| SHARE04 | 过期、取消、重复接受分别测试 | 状态准确且可恢复；同一成功请求重试返回原关系 |
| SHARE05 | 双方互发文本、小附件、内容卡片 | 内容完整；确认前不获取私有正文；超限附件发送前被阻止 |
| SHARE06 | B 离线，A 发送可入邮箱消息，B 再上线 | 先显示入队，接收确认后显示送达；重复投递仅一条 |
| SHARE07 | 邮箱满、消息过期、断网、重启后重试 | 无伪造送达，状态可恢复，不重复分享 |
| SHARE08 | B 在线/离线时 A 分别撤销 | A 立即拒绝下一次受保护请求，重启或重新发现不复活关系 |
| SHARE09 | 撤销后访问私有卡片 | 新的正文获取被拒绝，界面说明已保存副本无法远程收回 |
| SHARE10 | 检查权限、日志、诊断、导出 | 不获得额外服务/根信任，邀请和关系秘密不泄露 |
| SHARE11 | 产品双节点 CI 和不同公网出口实机跑全流程 | 全流程通过后才声明完整跨网里程碑，LAN 结果不能替代 |

记录邀请→接受、接受→确认送达耗时，以及平台、网络范围和安全错误码。
