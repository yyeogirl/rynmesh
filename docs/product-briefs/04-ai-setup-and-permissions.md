# 04 AI 设置与好友权限

状态：需求草案，待开发与验收。优先级：第三批，分为本地设置和好友授权两部分。

## 1. 目标与流程

用户无需终端或 Docker，在应用内安装和恢复 AI；默认仅自己使用，之后可按好友授权。

查看设备推荐 → 确认模型 → 安装 → 检查就绪 → 首次问答 → 选择好友授权 → 好友使用 → 可撤销。

## 2. 功能需求

| 功能 | 具体规则 |
|---|---|
| 设备推荐 | 按硬件显示支持档位、下载大小、空间需求和运行方式；不支持的平台明确提示 |
| 安装确认 | 展示模型来源、许可入口和资源需求，确认后下载，不静默下载大模型 |
| 安装状态 | 下载、校验、准备、就绪；进度依据实际字节和已验证检查点 |
| 恢复与取消 | 下载可中断恢复，取消状态真实；损坏文件重校验，未完成模型不可用 |
| 就绪检查 | 实际模型加载和推理检查通过才可用，进程/端口在线不等于模型就绪 |
| 首次问答 | 就绪后进入 Ask Ryn，重启后恢复配置并重新检查可用性 |
| 安装管理 | 可查看模型与占用、停止或移除；移除前说明范围，不删除会话 |
| 默认权限 | 仅自己使用，建立好友关系不会自动获得 AI 权限 |
| 指定授权 | 选择好友和允许使用的服务，可查看和撤销；授权结果双方可见 |
| 服务端检查 | Provider 检查关系、权限版本、服务范围和重放，不能只靠隐藏 UI |
| 处理中撤销 | 立即拒绝新任务；旧任务尝试取消并展示实际状态，无法立即停止时说明仍在处理；结算一次 |

## 3. 异常与恢复

- 空间不足、网络中断、校验失败分开提示，提供清理/重试入口。
- runtime、CUDA 或依赖缺失按实际配置提示，CPU 路径不强制要求 CUDA。
- 模型忙碌提供等待/重试，不宣告节点离线。
- 好友离线、未授权、已撤销分别提示，不自动改用另一服务。
- 授权失败保持原权限，不提前显示授权成功。

## 4. 范围与复用

复用主线原生 runtime、硬件检测、安装接口及 #41 相关候选代码；好友授权依赖稳定关系与双节点测试。
首版不含配额、定时共享或新的收费体系；已有计费服务保持原结算规则。

## 5. 验收标准

同时满足 [通用验收标准](README.md#通用验收标准)。

| 编号 | 操作或条件 | 通过条件 |
|---|---|---|
| AI01 | 支持平台的干净桌面，无 Docker | 不用终端完成模型安装和真实问答 |
| AI02 | 查看推荐并安装 | 来源、许可、大小和空间需求可见，确认后下载 |
| AI03 | 下载中断、取消、重启后继续 | 依据验证进度恢复，无重复安装，未完成不标就绪 |
| AI04 | 校验失败、移走模型、依赖缺失 | 错误明确且可恢复，不发布假健康服务 |
| AI05 | 就绪后重启问答 | 配置保留，重新核对健康，可获得真实回答 |
| AI06 | 未授权好友直接请求 | Provider 拒绝，好友关系本身不开放 AI |
| AI07 | 仅允许 B 用模型 X，C 未授权 | B 可发现使用 X；C 及 B 对其他未授权模型的请求被拒绝 |
| AI08 | B 执行中被撤销，再发新任务 | 新请求立即拒绝，旧任务状态真实且只结算一次 |
| AI09 | 重放旧凭证、重启、重新发现好友 | 旧权限不复活，需新的明确授权 |
| AI10 | 停止/移除模型后查看历史 | 运行状态和空间更新，会话保留，对应模型入口显示不可用 |

本地设置提供打包应用实机证据，好友授权提供双节点调用与拒绝证据；按平台分别验收。
