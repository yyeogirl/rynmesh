## 1. 本轮目标与顺序

先交付两个可独立演示的结果：

1. 新用户安装后，不配置模型、不连接好友，就能看到真实内容、打开阅读、保存或反馈，并能恢复来源故障。
2. 用户把邀请发给尚未安装 Ryn 的朋友，对方安装或打开应用后接受邀请，双方完成第一次分享，并能撤销关系。

随后用统一 Ask Ryn 串起阅读内容和已有 AI 服务；第三批完成本地 AI 设置与好友 AI 授权。

旧 `USER_PRODUCT_PRIORITY_ROADMAP.md` 和 `APPROVED_USER_REQUIREMENTS_DEVELOPMENT_SEQUENCE.md`
中的“首次成功 → 本地 AI → Ask Ryn → 我的内容 → 配对”顺序不再适合作为排期依据。
保留 DEV-01～DEV-05 编号用于追踪实现，但执行顺序调整为：

```text
基线适配
  ├─ 首次成功（DEV-01，含 #16 / #17）
  └─ 配对分享（DEV-05 / #30）＋我的内容最小列表（DEV-04 部分）
                 ↓
统一 Ask Ryn（DEV-03，逐步接入 #24 / #25）
                 ↓
本地 AI 设置（DEV-02）＋好友 AI 权限（#41）
```

## 3. 已确认的适配点

这些结论来自关键路径静态核对，不是完整安全审计。

1. **路由集中与重复持久化。** 候选套件把首次成功、助手、Library、Friends 的新端点
   加入 `peer_http.py`，例如首次成功端点在该分支约 1870 行。`first_success.py::_write`
   与 `assistant_runs.py::_atomic_json` 仍使用固定 `.tmp` 文件。迁入独立路由包，复用
   `rynmesh/atomic_io.py`，按主线版本化记录规范保留未知字段和迁移备份。
2. **两套好友模型。** 套件使用 `rynmesh/friends/` 包，旧 #30 分支使用
   `rynmesh/friends.py` 单模块。不能同时直接移入；第一批确定一种关系/邀请/撤销记录模型，
   第三批将旧 ACL 和深链适配到这个模型。
3. **跨 NAT 产品集成仍要做。** 套件 Friends 路径未见主线 mailbox 接入；目前复制的是
   `invite_uri`，没有“安装后粘贴”的完整邀请文案。邮箱至少一次投递，处理器要按业务身份
   幂等处理重复、乱序、过期和重启恢复。入邮箱不等于收件人已收到。
4. **#16 / #17 不能随引导完成自动关闭。** 现有页面主要是汇总健康、来源 chip 和反馈数；
   还需完整的逐来源检查/成功时间、缓存与单源重试，以及单条 More/Less/Hide 的解释和撤销。
5. **Ask Ryn 尚未统一到节点存储。** `assistantStore.ts` 调用 `llmConversationStore.ts`，
   后者使用加密 IndexedDB；节点端保存 run/context 不等于保存完整会话。
   增加节点端会话服务，旧浏览器记录仅由原浏览器读取迁移，幂等确认成功后再处理旧副本。
6. **助手任务要对齐新 runtime。** 候选 `assistant_runs.py` 为每次运行创建 daemon thread，
   未直接映射 `runtime_busy` / `p2p_capacity_exhausted`；远端 wrapper 没有显式将外层 run
   幂等键传到订单。将生命周期纳入现有后台机制，并验证任务、订单、结算身份贯通。
7. **“远端”不能直接标成“好友”。** 候选 `_assistant_targets` 把发现的远端服务统一标成
   Friend device。只有已建立且有效的好友关系才能显示好友标签；提供者身份、服务键和
   内容接收方都要真实可见。
8. **本地 AI 与文件提取有重复实现。** 套件在 `lifecycle.py` 自行下载/解压 runtime，
   `library_imports.py` 自行组织 PDF 子进程解析。分别适配主线 `runtime_native*` 与
   `services/document_extract.py`，不整文件覆盖现有实现。

## 4. 第一批：第一次阅读与第一次分享

### A. 首次成功（P0；DEV-01 + #16 + #17）

用户价值：安装后立即读到值得看的真实内容，并知道如何调整推荐。

交付范围：

- 无模型、无好友、Registry 暂不可用时，仍可通过可用公共来源或缓存阅读。
- 首页呈现真实推荐、继续阅读和需处理事项；引导可关闭，可从首页继续。
- 真实打开内容并保存或反馈后记录首次成功；关闭弹窗不能算完成。
- 每个来源显示健康、内容数、检查/成功时间、连续失败、缓存状态和单独重试入口。
- 展示反馈带来的推荐信号及原操作时间；可撤销一条误操作，并重新计算排序。
- 第一次成功后提供“连接朋友”的非阻塞下一步。
- #38 有可用内容时标注“来自 Ryn 网络”，不可用时保持真实来源降级体验。

验收：干净打包应用进入真实内容并完成操作；目标三分钟内完成，记录机器与网络条件下的
实测时间。覆盖单源失败、全失败有缓存/无缓存、无模型、关闭重开、反馈撤销与持久化。
每个路径页面覆盖加载、空、错误、有内容四种状态。#16 / #17 分别满足原 Issue 清单才关闭。

### B. 简单配对与分享（P0；DEV-05 / #30）

用户价值：把正在读的内容安全发给朋友，朋友能从邀请开始使用 Ryn。

交付范围：

- 可复制“安装地址＋一次性邀请＋有效期＋粘贴步骤”的文本，本地生成二维码。
- 接受前展示身份、端点/可达范围和本次授权；用户确认前不向待审核端点发起连接。
- 邀请过期/已消费给出重新邀请入口；安装耗时导致过期也有明确恢复路径。
- 完成加密文本、大小受限的小附件、内容卡片的第一次分享。
- 内容卡片展示来源与获取动作，接收方确认后才拉取；未授权时不自动下载。
- 支持已有邮箱的邀请接受/撤销通知/合适大小的离线消息路径；展示待发送、已入队、
  已送达、失败/过期、重试状态。超出邮箱容量的附件走现有传输或等待可达路径。
- 撤销在本地立即生效，远端通知可重试；旧邀请、重复消息、重新发现不能复活旧关系。

最小内容依赖：从 DEV-04 先提取已保存列表、继续阅读和“分享给朋友”选择器。
完整文件导入、批量操作不成为内容卡片的前置条件。

验收分两级：

- **功能 PR 验收：** 两个独立 node home，LAN/已可达端点完成邀请→接受→文本/附件/卡片→撤销，
  另覆盖未安装用户、离线重试、重复投递、过期、重启恢复。
- **完整 Friend Mesh 里程碑：** 接入 #37，自动跑完整两节点产品旅程，并在不同公网出口
  手动完成一次。仅 LAN 通过不能标记该里程碑完成；邮箱已合入也不等于产品跨网验收通过。

成功指标：邀请到接受耗时、接受到第一次真实送达耗时、重试后是否去重、撤销后下一请求是否拒绝。
采用本地验收记录或用户主动诊断，不新增集中行为追踪。

## 5. 第二批：Ask Ryn 接上内容与服务

### C1. 一个入口与一份节点端会话（P0；DEV-03）

- 先出小 PR：移除 `SearchAsk.tsx` seed 会话，主入口命名为 Ask Ryn，空状态给真实可用动作。

### C2. 切换 Provider 与就此内容提问（#24 / #25）

- 复用 #24 的服务比较与切换逻辑：别名、上下文窗口、价格和就绪状态可见。

无模型、模型未就绪、runtime 忙碌、容量不足、来源失效、超长文章均有对应动作。

A1→A2；A3 可独立于 A2 的 UI 提取推进。B1 可与 A 线独立，B2→B3，B3 只依赖最小内容列表。
C1→C2/C3；D1 在第一、二批完成后交付；E1 依赖 B 核心合入和 #37，E2 不阻塞首批配对。
如果 C1 的存储迁移或 B3 的组合仍过大，再拆成“后端兼容 API → UI 接入”，每次合入 main 均可运行。

建议容量：若主要由一位开发者负责，基线与协议梳理预留 1–2 个工作日；第一批约 2–3 周，
第二批约 1–2 周，第三批约 2–3 周。属于静态检查后的粗估，包含集成与针对性测试，不包含
外部 review 排队、#37 交付等待和缺少真机的等待；完成 A1/B1 后按实际差异重新估算。
多人时可分担 A/B 两线，不需要让首批阅读等待本地 AI。

## 8. 各批通用状态约定与发布门槛

| 真实状态 | 用户看到什么 | 可执行动作 |
|---|---|---|
| 节点在线、模型未就绪 | 应用可用；该 AI 尚未准备好及具体原因 | 阅读内容、配置/安装模型、选择其他服务 |
| `runtime_busy` | AI 正在处理任务 | 等待、按策略重试、显式选择其他服务 |
| `p2p_capacity_exhausted` | 当前连接容量已满 | 等待会话释放、重试、选择可用服务/路径 |
| 不可达 | 连接当前未建立 | 检查网络、重试；适用时等待邮箱投递 |
| HTTP 已取消但运算未确认终止 | 已请求取消，任务可能仍在处理 | 查看最终状态，防止重复提交和结算 |
| 消息已进入邮箱 | 等待对方收取 | 查看状态；不要提前显示已送达 |
| 邀请过期/权限撤销 | 邀请失效或当前无权访问 | 重新邀请或联系拥有者重新授权 |

- 固定 UDP 端口只支持一个活跃 ICE 会话；普通中转需要两条 ICE 连接，保留临时端口配置。
- 模型输出整段返回是受支持路径，不以流式支持作为成功条件。
- 每个 PR 的新行为带针对性测试；正式候选跑当前主线全量后端、前端、lint/build 和所需 CI。
- 每个用户功能交付可完整执行的旅程、所有可达失败状态、冷启动、重启恢复及脱敏验收步骤。
- 证据记录基线/实现 commit、环境、耗时、安全错误码、已知限制；不记录正文、Prompt、输出、邀请秘密或密钥。
- 平台构建、产品真机路径、真实 GPU、公网不同出口验收分别记录，互相不能替代。
- #22 当前 GitHub 状态已是 closed；不要沿用旧文档把它机械列作 open。对应硬件/公网
  发布声明仍应核对已有证据的提交和环境，本次 #48 未进行新的 V100/跨 NAT 硬件验收。
