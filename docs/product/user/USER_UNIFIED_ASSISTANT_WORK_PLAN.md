# 用户需求：统一 AI 助手入口

状态：产品需求草案  
优先级：P0  
建议顺序：本地 AI 启用之后

## 1. 一句话目标

用户只面对一个“Ask Ryn”助手，可以继续对话、搜索自己的内容、询问当前条目或
文件，并由 Ryn 自动选择本地 AI 或已授权的服务；用户不需要理解 Search & Ask、
Private AI、服务订单和侧边 AI 面板的区别。

## 2. 当前问题

现有 Webapp 同时存在：

- Search & Ask 页面；
- Private AI Chat 页面；
- 全局 AI curator 侧栏；
- 内容摘要和 Digest AI；
- Peer Chat。

这些入口背后的安全边界不同，但对用户来说都像“聊天”。Search & Ask 还以
硬编码的示例消息作为初始会话，Private AI 使用另一套本地加密会话存储，侧栏
主要展示策略而不能完成同一段对话。结果是功能被看见，却没有一个可以长期使用的
助手工作区。

Peer Chat 仍应保留为“人与人消息”，但 AI 入口应统一。

## 3. 用户故事

- 我在 For You 看到一篇文章，点击“问 Ryn”，直接询问文章内容；
- 我粘贴一个网页、添加 PDF 或文本文件，让 Ryn 基于该材料回答；
- 我问“最近保存的三篇本地 AI 文章有什么共同点”，Ryn 搜索我的本地内容；
- 我可以继续昨天的对话，并看到回答引用了哪些材料；
- 本地模型不可用时，Ryn 清楚告诉我可选方案，不偷偷把内容发到云端或其他节点；
- 高级用户可以查看本次回答实际使用了哪个 Provider、花费/额度和路由原因。

## 4. 信息架构

### 4.1 主入口

主导航只保留一个 `Ask Ryn`。支持：

- 从任意页面打开侧边快速问答；
- 点击“展开”进入完整助手工作区；
- 从内容查看器、我的内容和文件选择器创建带上下文的新会话。

侧边栏与完整页面使用同一会话、同一草稿和同一请求状态，不再是两个产品。

### 4.2 会话列表

- 新建对话；
- 最近会话；
- 搜索标题；
- 重命名、归档和删除；
- 显示上下文类型：普通、文章、网页、文件、多条收藏；
- 显示当前计算位置：本机、好友节点、明确授权的云端。

### 4.3 消息内容

每个回答可以包含：

- 正文；
- 引用卡片；
- 使用材料范围和截断提示；
- 本次路由的简洁说明；
- 可执行的后续建议；
- 失败后的重试、换模型或缩小上下文。

普通用户默认只看结果和引用。技术操作名、内部 endpoint、task/settlement 等细节
进入折叠的“运行详情”。

## 5. 上下文模型

统一支持以下上下文来源：

1. 当前内容条目及 Reader 抽取正文；
2. 用户保存的网页；
3. 本地文本、Markdown、PDF 和受支持文档；
4. 我的内容中的多个条目；
5. Ryn 的本地推荐证据和阅读记录；
6. 无附件的普通对话。

上下文对象建议版本化：

```ts
interface AssistantContextRef {
  version: "ryn.assistant-context.v1";
  id: string;
  kind: "content-item" | "web-page" | "local-file" | "library-selection";
  title: string;
  sourceRef: string;
  localSnapshotRef?: string;
  addedAt: string;
}
```

会话保存引用和经过用户确认的本地快照，不把大段正文放入 URL。正文快照必须进入
受保护的本地存储；如果沿用 Web IndexedDB，加密和密钥生命周期必须与现有
Private AI 会话一致。更推荐逐步迁移到 node 管理的统一会话存储，使桌面恢复、
导出和擦除语义一致。

## 6. Provider 与路由

### 6.1 默认策略

- 首选用户已选择且健康的本地模型；
- 没有本地模型时，引导启用本地 AI；
- 只有用户显式授权后，才显示云端或 Friend Mesh Provider；
- 含本地文件或私人历史的请求，不允许无提示切换到远端。

### 6.2 用户可见选择

输入框附近显示简洁计算位置：

- `在此设备上`；
- `好友设备：Alice 的 Ryn`；
- `云端：Claude`。

点击后展开模型、上下文窗口、预计费用/额度、在线状态和数据边界。Provider 的稳定
身份仍使用复合键，模型别名只用于展示。

### 6.3 自动路由

允许 Ryn 根据上下文大小和能力建议更合适 Provider，但必须：

- 在发送前展示变更；
- 对离开本机的数据重新取得必要授权；
- 永不把已有会话静默迁移到不同隐私边界；
- 保存每次请求的实际 Provider 身份和策略快照。

## 7. Prompt 与证据安全

- 文章、网页和文件内容一律视为不可信证据，不是系统指令；
- 使用明确、可转义的上下文边界；
- 在发送前按 Provider 上下文窗口做确定性预算；
- 截断必须在段落、页面或安全 Unicode 边界发生并提前提示；
- 引用必须能回到本地材料或原始来源；
- 无证据时明确说不知道，不能生成虚构引用；
- Prompt、附件正文和输出不得进入 Registry、普通日志或通知正文。

## 8. 会话生命周期

会话状态至少包括：

- `draft`：尚未发送；
- `submitting`：本地 node 接收请求；
- `running`：模型处理中；
- `completed`：存在可信最终结果；
- `cancelled`：用户取消；
- `failed`：安全失败，可重试；
- `partial`：若未来支持流式，部分文本不可作为完成结果。

取消、重试和应用重启后恢复必须保持幂等。只有最终完成结果进入正式会话记录；
未来流式增量不能单独触发成功或结算。

## 9. 搜索与工具能力

第一版仅允许低风险、只读能力：

- 搜索本地内容和 Digest；
- 打开引用；
- 读取用户明确选择的材料；
- 解释推荐原因；
- 创建建议的搜索或来源添加草稿。

任何发布、删除、信任 Peer、修改设置或网络访问扩展都需要单独的工具权限和确认，
不因“统一助手”而自动开放。

## 10. 实施切片

### Slice 1：统一会话领域模型

- 合并 Search & Ask 与 Private AI 的会话展示模型；
- 移除硬编码 seed 消息；
- 定义会话、消息、引用、上下文和 Provider 快照；
- 保留旧 Private AI 历史迁移或兼容读取。

### Slice 2：统一入口和真实对话

- `Ask Ryn` 完整页面；
- 全局侧栏复用当前会话；
- 普通本地问答、历史、取消和重试；
- 无模型时进入一键启用流程。

### Slice 3：内容与文件上下文

- 当前条目“一键询问”；
- 网页、文本和 PDF；
- 上下文卡片、删除和截断提示；
- 引用回跳。

### Slice 4：可控 Provider

- 本地/好友/云端的可见选择；
- 复合服务身份和对话绑定；
- 隐私边界确认；
- 费用与状态展示。

### Slice 5：可选流式输出

只有统一助手的非流式闭环稳定后再接入 streaming。流式是体验增强，不是统一入口
的前置条件。

## 11. 非目标

- 不把 Peer Chat 合并进 AI 会话；
- 不在第一版做自治 Agent 或写操作工具；
- 不支持浏览器绕过本地 node 直接请求 Provider；
- 不自动把私人文件发送给远端；
- 不要求第一版同时完成所有文件格式；
- 不以 streaming 作为上线门槛。

## 12. 验收标准

- [ ] 主导航只有一个清晰的 AI 助手入口。
- [ ] 快速侧栏和完整页面共享同一会话和草稿。
- [ ] 初始界面没有硬编码演示对话或虚假操作记录。
- [ ] 用户可创建、继续、重命名、归档和删除会话。
- [ ] 普通对话、当前文章和至少一种本地文件上下文可完整运行。
- [ ] 回答引用能打开对应的本地材料或来源。
- [ ] 上下文截断在发送前可见，且不会超过 Provider 限制。
- [ ] Provider 切换不会把旧会话静默发送到另一隐私边界。
- [ ] 无本地模型时进入可完成的启用流程，而不是只显示 CLI 指令。
- [ ] Prompt、正文和输出不进入 URL、普通日志、Registry 或通知。
- [ ] 取消、超时、失败重试和应用重启后状态一致。
- [ ] 旧 Private AI 会话有明确迁移、兼容读取或导出策略。

## 13. 用户验收脚本

1. 从首页打开 Ask Ryn，完成普通本地问答；
2. 收起为侧栏再展开，确认会话和草稿不丢失；
3. 从 For You 条目点击“问 Ryn”，基于正文提问并打开引用；
4. 添加一个本地文件，确认发送前显示计算位置和材料范围；
5. 取消正在运行的请求并重试；
6. 切换到不同隐私边界的 Provider，确认出现明确提示且旧会话不被静默迁移；
7. 重启应用并继续最近会话。
