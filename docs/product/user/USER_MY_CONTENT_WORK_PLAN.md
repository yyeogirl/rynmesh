# 用户需求：“我的内容”统一工作台

状态：产品需求草案  
优先级：P1  
建议顺序：统一助手之后，可与好友分享前期并行

## 1. 一句话目标

把收藏、稍后阅读、阅读历史、阅读进度、订阅源、网页监控和本地文件集中到一个
“我的内容”工作台，让用户能找回、整理和继续使用自己的材料。

## 2. 当前问题

底层已经保存阅读/播放进度、书签、完成状态、来源、网页 watcher 和部分缓存材料，
设置页也支持导出和擦除。但这些能力分布在 For You、内容查看器、Explore 和
Settings 中，没有一个用户可以明确回答以下问题的地方：

- 我保存过什么？
- 我上次看到哪里？
- 哪些网页正在监控？
- 我添加了哪些来源，它们是否健康？
- 哪些材料可以直接交给 Ask Ryn？
- 如何批量删除、导出或取消关注？

没有“我的内容”，Ryn 更像一次性推荐页，而不是会持续积累价值的个人助手。

## 3. 目标用户与核心任务

### 核心任务

1. 快速保存一个网页或推荐条目；
2. 在“我的内容”中找回它；
3. 从上次位置继续阅读或播放；
4. 对一项或多项内容询问 Ask Ryn；
5. 管理订阅源和网页变化监控；
6. 批量归档、移除或导出自己的记录。

### 成功感受

用户应该感到“Ryn 记住的是我主动保留和使用过的材料”，而不是“系统抓了很多我
无法管理的缓存”。

## 4. 信息架构

主导航新增或由 Explore 演进为 `我的内容`，包含以下视图：

### 4.1 已保存

- 收藏的推荐和网页；
- 用户手动添加的稍后阅读链接；
- 本地导入文件；
- 可按类型、来源、主题和时间筛选。

### 4.2 继续阅读

- 有阅读/播放进度但未完成的内容；
- 显示上次打开时间和进度；
- 默认按最近活动排序；
- 已完成项目可从此视图隐藏，但仍保留在历史中。

### 4.3 历史

- 已打开和已完成内容；
- 支持日期、类型和来源筛选；
- 支持单项移除和按时间段清理；
- 清理前说明会同时移除哪些进度或书签状态。

### 4.4 来源与监控

- 用户添加和系统默认来源分组展示；
- 逐来源显示最后成功、最近错误、缓存使用和下次重试；
- 支持添加 RSS、YouTube channel、subreddit；
- 显示正在监控的网页及最后变化时间；
- 支持暂停而不删除配置。

### 4.5 文件

- 用户明确导入的本地材料；
- 显示文件名、类型、大小、导入时间和索引/解析状态；
- 默认不发布到 Mesh；
- 支持打开、问 Ryn、从库中移除；
- “移除记录”和“删除原文件”必须是两个不同操作。

## 5. 通用交互

### 5.1 保存入口

以下位置使用统一“保存”动作：

- For You 卡片；
- 内容查看器；
- Explore 条目；
- 浏览器/桌面分享入口（后续平台支持）；
- URL 粘贴框。

保存后立即进入本地库，并显示可撤销通知。重复保存同一稳定内容 ID 或规范化 URL
时不创建不可理解的重复项。

### 5.2 搜索与筛选

- 搜索标题、来源和本地提取文本；
- 筛选：内容类型、状态、来源、标签、是否可被 Ask Ryn 使用；
- 排序：最近保存、最近打开、未完成、标题；
- 搜索默认只访问本地索引，不将用户查询发送到外部来源。

### 5.3 批量操作

- 加入 Ask Ryn 上下文；
- 标记已读/未读；
- 归档；
- 移除收藏；
- 导出元数据或选中材料；
- 删除必须显示影响范围并支持安全确认。

### 5.4 内容状态

统一状态词汇：

- `saved`：用户主动保存；
- `in_progress`：存在未完成进度；
- `completed`：用户完成；
- `archived`：保留但不出现在常用视图；
- `source_unavailable`：来源暂不可达，本地记录仍存在；
- `local_copy_missing`：曾有本地快照，但文件已不可用。

推荐学习信号和内容保存状态必须分离。“不感兴趣”不等于删除历史，“取消收藏”也
不应自动撤销已经产生的推荐信号。

## 6. 数据模型建议

现有 consumption 记录可扩展为统一 LibraryItem 投影，但不要复制多个相互漂移的
真相源：

```json
{
  "version": "ryn.library-item.v1",
  "library_id": "...",
  "content_id": "...",
  "canonical_url": "...",
  "title": "...",
  "kind": "article",
  "source_id": "...",
  "saved_at": "...",
  "last_opened_at": "...",
  "progress": 0.42,
  "completed": false,
  "archived": false,
  "local_snapshot_ref": "...",
  "user_tags": []
}
```

关键规则：

- 使用稳定 content ID；外部网页使用规范化 URL 辅助去重；
- 对用户行为记录迁移版本；
- 列表查询、分页和筛选有上限；
- 正文和附件不直接塞入列表响应；
- 删除本地快照不应破坏保留的元数据，除非用户选择完整删除；
- 所有记录进入个人数据导出和范围化擦除。

## 7. 与推荐系统的关系

“我的内容”不是另一个推荐页：

- 保存、打开、完成可以作为正向或弱正向信号；
- 用户应能查看哪些操作影响了推荐；
- 撤销反馈与移除收藏分别处理；
- 已归档内容默认不继续高频推荐；
- 本地文件除非用户主动设置，不参与公开内容推荐；
- 来源暂停后保留历史，停止未来抓取。

## 8. 与 Ask Ryn 的关系

- 单项操作：“问 Ryn”；
- 多选操作：“比较所选内容”；
- 在发送前显示材料数量、可用正文范围、截断和计算位置；
- 用户可以从会话移除材料，而不删除 Library 中的原项；
- AI 生成内容默认不回写或覆盖原始材料。

## 9. 隐私与文件安全

- 本地文件导入不等于发布；
- UI 明确区分“仅此设备”“发送给好友 Provider”“发布到 Mesh”；
- 原始本地路径不进入公开 Manifest、Registry、普通日志或远端 Prompt；
- 文件预览和解析有大小、类型、超时和压缩炸弹防护；
- 删除原文件需要系统文件权限和单独确认，默认只删除 Ryn 的引用/快照；
- 浏览历史、收藏、标签和本地索引可以独立导出和擦除。

## 10. 实施切片

### Slice 1：统一查询与状态

- 在 node 端提供分页 Library 查询；
- 统一 consumption、bookmark、read-later 和 watcher 投影；
- 明确去重和迁移规则。

### Slice 2：已保存与继续阅读

- 新的“我的内容”页面；
- 保存、取消、继续和进度；
- 搜索、筛选和空状态。

### Slice 3：来源与监控管理

- 迁移 For You 中的来源/监控管理；
- 展示健康、缓存、错误和恢复操作；
- 暂停、恢复和删除。

### Slice 4：本地文件

- 安全导入；
- 解析/索引状态；
- 打开和问 Ryn；
- 引用移除与原文件删除分离。

### Slice 5：批量操作与导出

- 多选比较；
- 归档与批量移除；
- 可理解的导出和擦除。

## 11. 非目标

- 不做云同步或跨设备自动同步；
- 不构建完整文档管理系统；
- 不默认索引用户整个硬盘；
- 不自动发布本地文件；
- 不把缓存内容都冒充成用户收藏；
- 不在第一版支持任意二进制格式的全文解析。

## 12. 验收标准

- [ ] 用户能在一个页面找到所有收藏、继续阅读、历史、来源和监控。
- [ ] 从 For You 保存的内容立即出现在“已保存”。
- [ ] 阅读/播放进度在重启后恢复。
- [ ] 用户可按标题、类型、来源和状态搜索筛选。
- [ ] 来源失败不会删除历史，并显示最后成功和恢复操作。
- [ ] 暂停来源停止未来抓取但保留现有内容。
- [ ] 至少支持安全导入文本、Markdown 和 PDF，并显示解析状态。
- [ ] 本地文件默认不会发布或发送到远端。
- [ ] 多选内容可以作为统一助手上下文，发送前有范围和隐私提示。
- [ ] 移除 Library 项和删除原文件是明确分离的操作。
- [ ] 导出和擦除覆盖新增记录、标签、快照及索引。
- [ ] 大型内容库使用分页，交互和 API 不做无界加载。

## 13. 用户验收脚本

1. 从 For You 保存两项内容；
2. 打开其中一项并阅读到一半；
3. 重启应用，从“继续阅读”恢复；
4. 添加一个 RSS 和一个网页监控，模拟来源失败并恢复；
5. 导入一份本地 PDF，确认不会自动发布；
6. 选择三项内容交给 Ask Ryn 比较；
7. 移除 PDF 的 Ryn 记录，确认原文件仍存在；
8. 导出数据并清理选定历史范围。
