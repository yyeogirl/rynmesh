# 用户需求：首次启动三分钟获得价值

状态：产品需求草案  
优先级：P0  
建议顺序：第一个开发  
目标版本：下一个用户体验版本

## 1. 一句话目标

普通用户第一次打开 Ryn 后，不理解节点、Registry、Peer、Transport 或 Credits，
也能在三分钟内完成“看到真实推荐 → 打开一项内容 → 保存或反馈”的第一个闭环。

## 2. 为什么优先

当前程序已经能自动发现公共内容、生成 For You、阅读内容、记录收藏和反馈，
但首次体验主要在解释系统结构和远期能力。主导航同时暴露 Home、For You、
Explore、Search & Ask、Publish、Peers、Services、Chat 和 Settings，用户必须自己判断
从哪里开始。

这会产生三个产品问题：

1. 用户先看到“本地节点控制台”，而不是 Ryn 能立即替他完成什么；
2. 正在获取内容、暂时失败、没有模型、没有 Peer 等状态需要用户自己理解；
3. 即使后台能力正常，用户也可能在第一次成功操作之前离开。

## 3. 目标用户与核心场景

### 3.1 目标用户

- 第一次安装桌面应用的非技术用户；
- 不准备配置服务器、模型或网络的个人用户；
- 想先验证“这个产品对我有什么用”，再决定是否配置高级能力的用户。

### 3.2 核心场景

用户安装并打开 Ryn。应用自动检查本地服务，随后直接进入一个任务式欢迎页：

1. Ryn 告诉用户正在准备第一批内容，并显示可理解的进度；
2. 默认公共源产生内容后，立即展示 3–5 个真实条目；
3. 用户打开其中一个条目；
4. 用户选择“保存”“更多类似”或“不感兴趣”；
5. Ryn明确反馈“已根据你的选择调整”，并进入正常首页。

完成这五步即视为首次成功。模型、Peer、发布和 Credits 都不是完成首次成功的前置条件。

## 4. 产品原则

- **先完成任务，再解释架构。** 技术细节放到“系统状态”和“了解更多”。
- **默认路径零配置。** 不要求账号、API Key、模型、Peer 或订阅源。
- **所有等待都有状态。** 说明正在做什么、通常需要多久、失败后怎么办。
- **高级能力渐进展示。** 用户完成首次成功后，再推荐启用 AI、添加来源或连接好友。
- **不伪造成功。** 不用 fixture、演示卡片或硬编码推荐冒充真实结果。

## 5. 用户体验设计

### 5.1 首次启动状态机

```text
启动桌面应用
  → 检查本地节点
  → 检查默认内容源
  → 获取或加载缓存内容
  → 展示首批推荐
  → 用户打开内容
  → 用户保存或反馈
  → 首次成功完成
```

建议使用明确状态：

- `starting_node`：正在启动本地服务；
- `checking_sources`：正在检查内容来源；
- `loading_cached_content`：网络暂不可用，正在加载已有内容；
- `ranking_first_items`：正在为用户准备首批内容；
- `ready`：首批内容可操作；
- `degraded`：部分来源不可用，但仍有内容；
- `needs_action`：无法继续，需要用户重试或查看诊断。

状态必须来自本地 node 的真实结果，而不是仅由前端计时器模拟。

### 5.2 欢迎页

欢迎页只回答三个问题：

1. Ryn 当前在做什么；
2. 用户现在可以做什么；
3. 如果失败，下一步是什么。

首屏不展示 Peer ID、Registry 地址、Credits 或安全协议。可以保留一个折叠的
“系统状态”，供高级用户查看 daemon、网络和来源健康。

### 5.3 首批内容

- 显示 3–5 个来自真实默认来源的条目；
- 显示标题、类型、来源、简短推荐理由和安全/可用状态；
- 默认主操作是“打开”；
- 打开后提供“保存”“更多类似”“不感兴趣”；
- 对暂不可内嵌的内容，明确跳转到原始来源，不把错误页面当内容。

### 5.4 完成反馈

首次反馈后显示简短结果，例如：

> 已保存。Ryn 会把这个主题作为后续推荐信号，你随时可以撤销。

随后提供三个非阻塞下一步：

- 继续浏览 For You；
- 添加一个喜欢的来源；
- 启用本地 AI。

### 5.5 回访首页

首次成功后，首页从“控制台总览”改为用户任务首页，优先展示：

- 今天为你准备的内容；
- 继续阅读和已保存内容；
- 需要用户处理的故障或确认；
- 最近一次学习变化；
- 可选的 AI 和好友能力入口。

Daemon、Registry、Peer 数量等运行信息进入次级“系统状态”区域。

## 6. 失败与恢复

### 节点启动失败

- 显示自动重试进度和最后一次安全错误分类；
- 提供“重新启动本地服务”；
- 提供“复制诊断信息”，但不包含密钥和个人内容；
- 桌面壳可恢复时不要求用户打开终端。

### 全部公共源失败

- 如果存在缓存，继续显示缓存并标注更新时间；
- 如果没有缓存，显示“重试”和“添加来源”；
- 展开后显示逐来源健康信息，不把内部异常栈直接暴露给用户。

### 部分来源失败

- 不阻断首次成功；
- 告知“正在使用其余健康来源”；
- 后台按现有有界策略重试。

### 用户关闭引导

- 保留进度；
- 首页显示一个轻量“完成首次设置”入口；
- 不反复弹出模态窗口阻挡使用。

## 7. 数据与接口建议

新增一个聚合的本地首次体验状态接口，避免 Webapp 自己拼接多个异步结果：

```json
{
  "version": "ryn.first-success.v1",
  "phase": "ready",
  "node_ready": true,
  "content_ready": true,
  "item_count": 18,
  "healthy_sources": 7,
  "source_count": 9,
  "using_cache": false,
  "first_item_opened": true,
  "first_signal_recorded": false,
  "recoverable_actions": []
}
```

建议记录本地里程碑：

- 首次节点就绪；
- 首批真实内容就绪；
- 首次打开内容；
- 首次收藏或反馈；
- 首次成功完成时间。

这些数据仅保存在本地，可进入个人数据导出和擦除范围，不需要集中遥测。

## 8. 实施范围

### Slice 1：状态聚合和错误分类

- 聚合节点、发现、来源健康和首次使用进度；
- 为桌面启动失败、来源失败和空内容定义稳定错误码；
- 保留现有底层接口兼容性。

### Slice 2：任务式欢迎页

- 替换当前以功能介绍为主的首次引导；
- 接入真实推荐和真实进度；
- 支持关闭、恢复和继续。

### Slice 3：首次内容与反馈闭环

- 打开真实内容；
- 完成保存或反馈；
- 展示学习结果和撤销入口。

### Slice 4：首页重构

- 以今日内容、继续阅读、行动事项为主；
- 技术运行信息降级到系统状态；
- 为后续本地 AI、我的内容和好友连接保留卡片入口。

## 9. 非目标

- 不在本需求实现模型下载安装；
- 不要求连接 Peer 或 Registry 才能完成首次成功；
- 不重写推荐算法；
- 不新增集中式账号和强制遥测；
- 不在欢迎页讲完整协议、经济系统或远期路线图。

## 10. 验收标准

- [ ] 全新数据目录启动后，用户无需配置即可看到真实内容。
- [ ] 用户能在三分钟内完成打开内容并保存或反馈。
- [ ] 没有模型、没有 Peer、Registry 离线均不阻断默认首次成功。
- [ ] 首次路径不显示 fixture 或硬编码内容。
- [ ] 每个等待状态都有进度、解释和恢复操作。
- [ ] 部分来源失败时仍可完成首次成功。
- [ ] 全部来源失败时能使用缓存或给出明确恢复路径。
- [ ] 用户关闭应用再打开后，进度可以恢复。
- [ ] 完成后不再强制弹出引导，并能从帮助中重新打开。
- [ ] 首次里程碑只保存在本地，可导出、可擦除。
- [ ] Webapp 交互测试、后端状态测试、打包桌面冷启动验收通过。

## 11. 用户验收脚本

在一台从未运行过 Ryn 的机器上：

1. 安装并启动应用；
2. 不填写任何设置；
3. 等待首批真实内容；
4. 打开一项内容；
5. 保存或点击“更多类似”；
6. 确认首页反映该操作；
7. 关闭并重新打开，确认不会丢失进度；
8. 分别模拟单来源失败、全部来源失败和 Registry 离线。

验收材料应记录耗时、页面状态和错误分类，不包含阅读内容正文或本地路径。
