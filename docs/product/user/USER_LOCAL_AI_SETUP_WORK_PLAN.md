# 用户需求：一键启用本地 AI

状态：产品需求草案  
优先级：P0  
建议顺序：首次成功之后，统一助手之前

## 1. 一句话目标

用户在 Ryn 应用内完成“检测设备 → 选择模型 → 下载/安装 → 健康检查 → 第一次回答”，
不需要自己访问 Ollama 网站、打开终端或复制命令。

## 2. 当前问题

Ryn 的推荐默认不需要模型，但 Search & Ask、摘要和部分 Digest 能力需要可用的
ModelProvider。当前设置页能检测和选择已安装的 Ollama 模型；当 Ollama 未运行时，
界面要求用户前往外部网站安装，并执行 `ollama pull ...`。

这意味着“本地 AI 助手”对普通用户并不是应用内可完成的能力。用户无法判断：

- 这台机器适合什么模型；
- 需要多少磁盘和内存；
- 下载是否仍在进行；
- 失败后应继续、重试还是换小模型；
- 模型是否真的能完成 Ryn 的第一次请求。

仓库已经有硬件检测、GGUF 校验、受管模型下载、运行时启动和 self-test 基础，
本需求主要把这些能力做成安全、可恢复的桌面产品流程。

## 3. 用户故事

### 新用户

> 我希望点击“启用本地 AI”后，Ryn 自动推荐适合我电脑的选项，并在安装完成后
> 让我立即问一个问题，而不是让我理解模型运行时。

### 已有 Ollama 用户

> 我希望 Ryn 自动发现我已安装的模型，让我直接选择，不重复下载。

### 高级用户

> 我希望连接现有的 loopback OpenAI-compatible API 或导入 GGUF，但这些高级路径
> 不应干扰普通用户的默认流程。

## 4. 产品范围

### 4.1 入口

- 首次成功后的“启用本地 AI”卡片；
- 统一助手在无模型时的就地启用入口；
- Settings → AI 中的管理入口。

三个入口进入同一个安装状态机，不能各自维护不同逻辑。

### 4.2 设备检测

显示用户能理解的结果：

- 可用内存与可用磁盘；
- 是否检测到受支持 GPU；
- 推荐档位：轻量、平衡、质量优先；
- 每个档位的预计下载大小、运行内存和用途；
- 明确说明所有推理是否保持在本机。

默认只突出一个“推荐”选项，其余放在“其他选择”。

### 4.3 安装模式

优先级如下：

1. **复用已运行的 Ollama。** 自动列出已安装模型并选择合适项；
2. **Ryn 受管模型。** 应用下载经固定 SHA-256 校验的模型和受支持运行时；
3. **连接本地 API。** 高级用户填写 loopback 地址并做健康检查；
4. **导入 GGUF。** 高级用户选择本地文件，Ryn 原地使用且不擅自删除。

不要在用户未选择云服务时自动降级到云模型。

### 4.4 安装进度

状态至少包括：

```text
检查设备
  → 准备下载
  → 下载模型
  → 校验文件
  → 准备运行时
  → 启动模型
  → 健康检查
  → 第一次回答测试
  → 完成
```

每一步显示：当前动作、百分比或确定/不确定进度、已下载大小、可安全执行的操作。
关闭窗口或应用重启后应恢复任务状态，不应从零重复下载完整文件。

### 4.5 第一次回答

安装成功后提供一个短测试问题。验收的不只是端口健康，而是：

- Ryn node 能找到所选 Provider；
- 能完成一条真实推理；
- 超时和上下文配置合理；
- 结果能回到 Browser；
- 不经过云端或 Peer。

测试内容不进入推荐学习或正式会话历史，除非用户主动选择“保存为新对话”。

## 5. 安全与资源规则

- 模型 URL、运行时版本和摘要必须固定并可审计；
- 下载仅允许 HTTPS，并校验 SHA-256；
- 不执行来自模型仓库的任意脚本；
- 下载、解压和运行时准备必须有空间上限；
- 不在日志中记录 API Key、完整 Prompt 或模型输出；
- 外部 API 默认只允许 loopback；非 loopback 必须二次确认并说明数据边界；
- 导入的用户模型默认永不由 Ryn 卸载或删除；
- 删除受管模型需要单独高风险确认；
- 模型进程崩溃时不得拖垮本地 node 和默认推荐功能。

## 6. 状态与持久化

建议增加版本化安装任务记录：

```json
{
  "version": "ryn.local-ai-install.v1",
  "job_id": "...",
  "mode": "managed",
  "phase": "download_model",
  "percent": 43,
  "bytes_done": 123,
  "bytes_total": 456,
  "resumable": true,
  "cancelable": true,
  "selected_profile": "balanced",
  "safe_error": null
}
```

要求：

- 同一时间只允许一个受管安装任务；
- 状态写入原子化；
- 任务可查询、取消、继续和清理；
- 取消下载时保留可安全续传的临时文件；
- 校验失败的文件不能进入运行状态；
- 重启后对残留任务做一致性检查。

## 7. 错误与恢复

### 磁盘不足

安装前阻止开始，显示所需与可用空间，允许选择更小模型。

### 内存不足

不启动明显超出保守限制的模型；建议轻量档位。

### 下载中断

保留受控临时文件并允许继续；重复点击不创建多个下载任务。

### 校验失败

隔离损坏文件，明确提示重新下载；不得尝试运行。

### 端口占用或运行时失败

选择可用受控端口或提供安全错误说明；不要求用户自己查进程。

### 模型可运行但响应过慢

测试超时后推荐更小模型，并保留当前安装供用户选择。

### Ollama 已安装但未运行

桌面能力允许时提供“启动 Ollama”；否则给出平台相关的一步操作，不首先展示 CLI。

## 8. 实施切片

### Slice 1：统一模型能力接口

- 把 Ollama、受管 GGUF、导入 GGUF 和本地 API 暴露为统一的安装/连接状态；
- 复用现有硬件检测、生命周期和 self-test；
- 新增稳定、安全的错误码。

### Slice 2：可恢复后台任务

- 安装任务注册、进度、取消、恢复；
- 与桌面退出、重启和更新流程协调；
- 限制并发和磁盘占用。

### Slice 3：安装向导

- 推荐档位；
- 下载与校验进度；
- 错误恢复；
- 高级路径折叠展示。

### Slice 4：第一次回答和运行管理

- 真实端到端本地推理测试；
- 切换、停止、修复和删除受管模型；
- 模型不可用时不影响非 AI 功能。

## 9. 非目标

- 不内置未经审核的任意模型市场；
- 不自动启用云模型；
- 不训练或微调模型；
- 不把远程 Friend Mesh Provider 当成本地 AI 安装；
- 不保证所有 GPU、模型格式和第三方运行时；
- 不在第一版支持多个模型同时常驻。

## 10. 验收标准

- [ ] 无 Ollama、无 Python、无终端操作的受支持桌面环境可完成受管模型安装。
- [ ] 已有 Ollama 用户可直接选择已安装模型，不重复下载。
- [ ] 硬件建议会阻止明显不可运行的选择，并提供更小选项。
- [ ] 下载可显示进度、取消、失败重试和应用重启后恢复。
- [ ] 模型与运行时摘要校验失败时拒绝启动。
- [ ] 安装完成后真实本地问答通过，而不只是健康端点通过。
- [ ] 默认路径不把 Prompt 发送到云端或 Peer。
- [ ] 模型崩溃、下载失败和磁盘不足不影响推荐和内容浏览。
- [ ] 用户导入的模型不会被 Ryn 静默移动或删除。
- [ ] 卸载受管模型有明确空间回收结果和高风险确认。
- [ ] Windows、macOS 和后续 Linux 的支持矩阵及限制清晰。

## 11. 用户验收脚本

至少覆盖四种干净环境：

1. 没有 Ollama：选择推荐模型并完成第一次回答；
2. 已有 Ollama 和多个模型：复用并切换模型；
3. 下载中途断网并重启应用：恢复后完成安装；
4. 磁盘或内存不足：阻止错误安装并推荐可行选项。

记录下载、启动、首个回答时间和安全错误码，不记录测试 Prompt/输出正文。
