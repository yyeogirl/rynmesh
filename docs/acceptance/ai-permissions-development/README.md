# 好友 AI 权限开发验证

日期：2026-09-11。范围为权限存储、Owner HTTP 接口、Provider 强制检查、好友私密发现与授权界面；AI06–09 未完整验收。

## 当前实现

- 默认仅本人使用。其他签名节点即使已成为好友、服务已发布，也必须持有该好友关系和服务对应的当前授权版本。Provider 在推理及任务重放前检查，失败返回加密的 `ai_permission_denied`，不进入模型。
- `GET /api/local/ai-access` 与 `PUT /api/local/ai-access/{service_id}/{relationship_id}` 需要 Owner 身份。写入采用版本条件，原子提交后才返回结果；相同请求的上一轮丢失响应可确认，旧版本不能覆盖新的选择。
- `ai-access/permissions.json` 使用 `ryn.ai-access.v1`，上限 2 MiB、5000 条授权。保留未知字段，拒绝未知版本，使用原有私有文件写入和文件事务。好友关系重新建立不会继承旧关系的授权。
- 请求里的 `ai_permission` 在原签名加密消息内，并进入消费者和 Provider 的任务指纹。本人请求继续复用本地执行路径，无需好友授权。
- 撤销提交后立即检查运行中的请求，`llm.friend-permissions` 工作器每秒复查。适配器取消仅表示尝试；模型线程未结束时运行计数不提前归零。授权已撤销但取消接口暂时失败，返回 `pending`，不回滚授权。
- Provider 保留已有发布/暂停开关和结算规则。好友页面可按好友与模型确认授权、撤销和查看保存结果；模型管理入口用于恢复未就绪服务。
- 好友通过已配对关系认证并加密查询可用服务。只返回当前关系获准的服务和权限版本；未授权、已撤销、模型不可用分别显示。缓存 120 秒失效，查询失败清除旧可用状态，撤销好友关系后不再展示缓存服务。
- Ask Ryn 预览和任务提交绑定同一授权版本；权限改变后不能静默换用新版本提交旧预览。好友服务可以使用配对时确认的地址，不依赖双方共享注册目录。

## 验证与边界

- 使用三个独立节点身份、真实签名和加密、真实好友/权限/订单文件，模型使用明确的测试替身。
- 覆盖未授权好友、其他签名节点、其他模型、授权成功、相同任务重放、撤销、重新构造 Provider、旧权限版本、重新授权及撤销好友关系。
- 阻塞模型用例中，Owner 撤销后拒绝新任务；取消适配器返回不能立即停止，原线程继续运行，直到显式放行才结束为取消。它不证明真实 GPU 可以立即停算，也不替代完整双节点结算验收。
- Owner 路由未认证请求被拒绝；取消通知失败仍保留已提交的撤销；重装路由后处理器及现有 HTTP Provider 使用当前权限状态。
- 本轮全后端 1048 passed / 29 skipped（174.14 秒）。随后动态权限回调和工作器配置专项 112 passed / 4 skipped；新增 HTTP Provider 重装验证后，权限接口专项 4 passed。新增 HTTP 用例未计入前述全量数量。
- 原协议和计费用例显式注入授权检查替身，以继续隔离验证原协议行为；这里的权限专项使用默认强制策略，没有注入放行回调。

## 双节点真实模型验证

证据：[Windows 双节点原生模型记录](windows-two-node-native.json)。使用两个独立节点进程、各自私有文件注册目录、浏览器界面与真实 llama.cpp b10774 / Qwen2.5-0.5B GGUF；调用发生在同机回环地址。

- 在浏览器完成邀请、接受、启用分享和针对好友授权。仅成为好友没有 AI 权限；获准后好友可私密发现服务，在 Ask Ryn 提问“7 加 8”得到 `15`。
- 第二个长回答在手动撤销前已完成，记录保留其 256 token 截断结果，不作为取消成功证据。
- 另一个真实请求由验收脚本提交，在 Provider 文件记录确认为 `running` 后立即撤销。原任务最终为 `cancelled`，运行占用归零；使用旧授权版本的新请求返回 `ai_permission_denied`，未创建 Provider 订单。
- 两个完成任务各结算一次 0.001 开发额度；取消任务的预留额度释放，没有结算或 Provider 收入。重复确认已完成请求未改变余额。
- 停止双方进程及原生运行时、确认端口关闭后重启，授权仍为 revision 4 / 不允许。启动已安装模型恢复就绪后，旧授权请求仍被拒绝；好友界面显示已撤销，原对话及回答仍可阅读。
