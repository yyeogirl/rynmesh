## 已接入

- 导航新增 Friend updates，选择有效好友后主动关注；成为好友不会自动订阅，也不会获得额外 AI、文件或内容权限。
- 消费记录可作为发布来源，复用现有文档快照、提取和私有副本模块。保存草稿与发布为两个操作；草稿变化不修改现有发布。
- 默认仅指定好友，按关系身份绑定授权。全部好友明确包含以后新增好友，必须在发布确认中同意。发布者能看当前有权访问者，页面明确区分权限、投递和阅读。
- 发布版本、操作身份和预期修订号防止重复提交及旧页面覆盖。新发布不会误标为已更新；修订保留原发布身份和发布时间。
- 同一套好友 HMAC 鉴权和 X25519 加密通信承载列表和正文请求。请求、响应及有界失败原因均加密并绑定请求身份；受众和拥有者本地文档标识不传给接收者。
- Provider 每次检查当前关系和发布受众；解析正文后再次检查，停止分享或撤权不能由旧列表、旧修订绕过。
- 最近列表每页 20 条；授权修订目录使接收端刷新第一页时也能清除后续页已撤销或过期的片段。重复刷新按发布身份合并；自动刷新保留已有分页进度。
- 关注状态、草稿、发布及已读版本写入节点密钥加密的原子存储。未知顶层/记录扩展保留，未知文件版本拒绝覆盖；当前上限为 512 条发布、512 条订阅、12 MiB 明文状态，正文复用已有 5 MiB 分享限制。
- 共享 `friend-feed.refresh` 工作器每轮间隔 3 秒，轮流检查已关注好友；失败记录到对应订阅，不阻止轮询其他好友。页面每 5 秒刷新本地状态，显示最后检查时间及恢复入口。
- 取消关注后的迟到响应不能重新写回；删除关系后本地更新入口隐藏。主动下载生成独立保存副本，撤销和取消关注均不删除副本或私聊。
- 页面重连后自动清除旧连接错误，操作失败提示单独保留；不把远端刷新失败当作订阅保存失败。

## 三个真实节点与浏览器

[实测记录](windows-three-node.json) 使用 Windows 上三个独立进程、独立目录、独立密钥，端口 18860/18861/18862；无模型，无公开注册和发现。

1. 通过实际 HTTP 邀请/接受建立 Author–Bob、Author–Carol 两组关系。文档为专门生成的本地合成种子。
2. 浏览器中 Author 选择已保存内容和 Bob，保存草稿；Bob/Carol 已关注但双方列表仍为空。
3. 浏览器确认发布后，Bob 自动出现一条更新，Carol 为零。首次观察距发布时间 51.572 秒，是观察上界，不能当作精确传输耗时。
4. Carol 直接获取被拒绝。最初 Owner API 显示泛化 503，改进加密错误响应后实测为 409 / `feed_publication_unavailable`；原始记录保留。
5. Bob 从实际页面选择保存并阅读，看到了正文，读状态变为 Read · Version 2。没有模型参与。
6. 停止全部三节点再用原目录启动，进程身份已变化；发布修订、关注、已读和独立副本均保留。
7. 通过实际 Owner API 将受众从 Bob 改为 Carol，发布修订变为 4。提交返回后约 1.703 秒观察到 Bob 列表清空、Carol 出现一条，Bob 旧获取返回 409。
8. 停止分享产生修订 5；约 3.094 秒内确认 Carol 列表为空且获取被拒绝。该时间包括观察与拒绝请求，不是精确到达时间。
9. Bob 保存副本的正文哈希在撤销及取消关注后均一致；浏览器已经打开的独立副本继续可读。
10. 最后又停止并重启 Bob，浏览器先显示连接错误，恢复后自动清除；没有手动清错误。全部验收节点和页面随后关闭，三个端口及实际进程均已确认释放。

上述为独立进程的 loopback HTTP 和浏览器证据，不是打包桌面、不同公网出口或跨 NAT 验收。

## 复现入口

在三个终端分别运行（选择新的专用目录，启动前构建 webapp）：

```powershell
python scripts/accept_friend_feed_node.py --home <rynmesh-feed-acceptance-author> --port 18860 --name "Feed Author" --seed
python scripts/accept_friend_feed_node.py --home <rynmesh-feed-acceptance-bob> --port 18861 --name "Feed Bob"
python scripts/accept_friend_feed_node.py --home <rynmesh-feed-acceptance-carol> --port 18862 --name "Feed Carol"
```

目录名必须以 `rynmesh-feed-acceptance-` 开头；脚本拒绝覆盖已有目录。重启时确认原节点已停止，使用相同参数添加 `--reuse`。首次种子曾因内部链接未转义而失败，已修复脚本，成功验收使用了新的 Author 目录。

打开各节点的 `/friend-updates`。先在 Friends 配对，再按上面的十步执行。受众调整也可从 Your publications 的 Edit draft and audience 进入，保存草稿、复核并重新发布；本次收窄受众的实测操作使用 Owner API，不能写成该页面步骤已验收。
