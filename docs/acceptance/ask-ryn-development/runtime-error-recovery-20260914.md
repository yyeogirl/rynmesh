# Ask Ryn 失败原因与原任务恢复验证（2026-09-14）

范围：ASK07 的后端错误传递与历史恢复；Windows 本机 HTTP 故障注入及生产存储/协议代码。没有进行本轮浏览器点击、打包桌面、真实 GPU 或公网 ICE 验收，不能据此将 ASK07 整项标为通过。

## 发现并修复

1. 原生运行时通过 HTTP 返回 `runtime_busy` 等明确原因，但适配器将其转成普通异常，Provider 最终只保留 `inference_failed`。现在读取有大小上限的错误包，只传递已知错误码；未知正文不进入用户回执。
2. Ask 任务回执校验只允许字母和下划线，错误地丢弃含数字的 `p2p_capacity_exhausted`、`p2p_transport_failed`。现在允许首字母后的数字，重启后仍保留原错误码。
3. 节点归档回答补充模型未就绪、模型不存在、运行时不可用、运行时连接失败与传输失败的原因和恢复提示。不会自动切换服务或重新提交任务。

## 实际验证边界

| 验证路径 | 结果 |
|---|---|
| 本机 HTTP 服务健康检查成功，生成返回 503 runtime_busy/model_not_ready/runtime_unavailable 或 404 model_not_found | 经真实适配器、签名加密请求、Provider、解密回执后保留对应失败码；运行槽释放 |
| HTTP 错误带额外私密标记、未知字符串、数组、null、嵌套 detail、超长正文 | 不把未知内容当成忙碌，不回显标记；错误文本有界 |
| 故障服务恢复为成功响应，重送同一签名任务 | 返回原失败回执，HTTP 推理调用数仍为 1 |
| 显式发送不同任务 ID | 成功收到合成回答，推理调用数为 2；这是故障恢复测试数据，不是真实模型回答 |
| 真实 socket 读取超时、向已关闭端口连接 | 分别为 inference_timeout 和 runtime_connection_failed；Windows 端口拒绝测试采用 10 秒上限，避免较短超时先触发 |
| 注入 12 种订单失败结果，经过 Ask 工作器与加密会话存储，再重新创建历史/工作器对象 | 原因与动作正确、原错误码保留，重复 begin 和工作器执行后仍只提交过 1 个任务 |

最后一项使用订单接口替身验证归档与幂等，不代表 12 种网络故障都已在浏览器或真实网络制造。P2P 错误的本轮证据只覆盖回执保存和提示，不覆盖真实 ICE 容量恢复。新任务恢复案例使用自有 Provider，不作为好友结算验收。
