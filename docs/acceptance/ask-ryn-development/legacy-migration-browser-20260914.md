# 旧浏览器会话迁移与恢复 · 2026-09-14

环境：Windows、本机生产节点和浏览器，真实 IndexedDB / Web Crypto 加密旧会话存储。两条旧会话为明确标记的合成迁移输入，分别绑定不同的旧 Provider 和模型，包含原时间、消息与任务 ID；不作为真实模型回答。没有预置节点迁移结果，也没有调用推理。

测试准备页仅由验收节点的 `--legacy-fixture` 显式开启，正常产品页面和生产构建未加入准备入口。页面使用现有 legacy store 的加密读写代码，不直接向节点写会话。

## 实际流程和结果

| 操作 | 验证结果 |
|---|---|
| 准备两个旧浏览器记录 | 两条密文记录、encrypted 模式；原始 IndexedDB 记录未包含消息明文 |

节点 PID 63424 → 55932。浏览器原件在失败后、节点停止期间和页面/节点重新载入后均为两条密文，内容摘要保持 `db7588d7cd07c69a418b2cb82a6b1cc131765c7e1e251907e9b513e82850fe3a`。这是专用数据准备页可见结果的记录，不是从浏览器工具直接读底层数据库。

整个过程原有七段节点历史摘要不变，原十笔订单身份不变，没有迁移导致的新推理。节点历史密文中未发现合成正文和测试 Provider 明文；这项检查不代表完整日志/导出隐私审计。

## 修复

前端原先对每个 HTTP 成功响应都增加 imported，包括 `already_imported`、`deleted`，甚至未识别状态。现在分别统计新增导入、节点已存在、因删除而跳过和需恢复；未知响应不能算成功。Ask 首页与聊天页共用结果格式，浏览器原件继续保留。

新回归先复现旧实现把四种响应都算新增，然后验证正确分类且不删除浏览器原件；页面用例验证真实分类文案。

- 迁移与两个页面专项 18 项通过；全部前端 44 个文件、241 项通过。
- TypeScript 与生产构建通过，保留既有大包提示。
- 三个 Python 验收脚本 Ruff 通过。后端产品代码没有改变，没有重复运行后端全套。
- [七个节点检查点和浏览器原件观察](migration-checkpoints-20260914.json)保留 ID、时间、摘要、计数和状态，不导出正文或凭证。

准备命令：`node scripts/build_legacy_browser_fixture.mjs`；节点命令：`python scripts/accept_ai_recovery_node.py --home D:/code/rynmesh-ai-recovery-acceptance --resume --legacy-fixture`。真实写入故障使用 `accept_reading_write_lock.py` 的固定 Ask 历史目标，停止辅助进程即释放，不改文件内容或权限。节点状态由 `observe_legacy_migration.py` 只读核对。
