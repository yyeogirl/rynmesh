# Ask Ryn 开发验证

日期：2026-09-11。分支：`codex/user-product-development`。本记录描述开发增量，ASK01–10 尚未完整验收。

## 当前实现

- 新增独立 `ask_ryn` 路由包，状态集中于 `app.state.ask_ryn`；使用注入节点的 home，重复安装后的路由读取最新实例和认证回调。
- 会话归本地节点所有，复用现有 messaging key 与独立加密域保存，整个历史文件不含明文消息、标题或 Provider 身份；原子写入与跨进程文件事务负责提交。
- 会话按原 Provider、服务键与网络绑定，修改不能迁移到其他服务；修订号阻止并发页面互相覆盖，相同写入可在响应丢失后重复确认。
- 删除留下不含正文的标记，迟到的写入和旧浏览器迁移都不能恢复已删除会话。未知存储字段保留，HTTP 返回及导出仅包含明确的历史字段。
- 浏览器旧记录显式迁移，保留原始 ID、Provider、服务键、时间和任务关联；节点迁移回执与导入记录一起提交，失败不确认，重复请求不覆盖新历史。浏览器加密原件暂作恢复副本，不自动删除。
- 现有 Private AI 聊天页在 live 模式下使用节点存储；fixture 模式继续使用原测试仓库。节点保存失败保留输入并阻止发单。
- 发送前持久化任务 ID，传给既有订单 API 的任务和幂等键。响应失败后的按钮只核对原任务，不直接重发；取消提示不声称 GPU 已经停止。

产品明确要求保留完整会话，因此正文存入专用加密历史，不进入任务结算记录、普通日志或状态错误。此处复用旧分支的交互与会话字段；没有复用旧分支的固定临时文件写入或浏览器权威历史方案。

## 统一入口、无模型草稿与历史增量

- `/ask` 成为统一入口；主页面、侧栏和原 Search & Ask / Private AI 地址均进入同一会话流程。移除旧示例问答及侧栏中写死的云模型状态。
- 没有模型时仍可读取历史、改名、导出、删除，进入本地模型设置。尚未选择模型的草稿单独加密保存，不生成假会话，不发起推理。
- 服务列表显示接收方身份、有效好友标识、模型、上下文窗口、价格和发现状态。选择新服务先展示接收方，再创建独立空会话；旧历史不复制过去。
- 显式请求的 Provider 或会话不存在时不再自动选择替代项。会话 ID 保存在 URL，刷新及侧栏定位使用同一记录。
- 后端历史/草稿专项 9 passed；类型检查和修改范围 Ruff 通过。新增草稿测试覆盖加密、节点重启、并发修订和未来格式拒绝。
- 本增量全前端 87 passed / 22 files，生产构建通过。

浏览器实际验证使用新建临时节点（本地 `127.0.0.1:18845`，无模型、关闭自动来源发现）。先确认没有示例会话，输入中文草稿并保存；停止该节点进程并以相同 home 重启后，重新加载页面，草稿恢复。随后由准备脚本加入一条明确标为合成案例的离线 Provider 历史，页面可以读取、改名，侧栏显示相同标题和同一 conversation ID。合成历史不是实际模型回答，不能据此认定推理和任务恢复已经验收。
