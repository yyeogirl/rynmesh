# 模型提供者切换与真实运行恢复 · 2026-09-14

范围：两个既有专用测试节点、独立身份与数据目录，Windows 原生 llama.cpp / Qwen2.5-0.5B CPU 模型、真实签名加密 HTTP 传输。两端模型别名相同，但 Provider 身份和服务键不同，切换涉及实际接收方变化。不是打包桌面、公网 NAT 或 GPU 验收。

## 页面切换流程

1. 通过页面创建邀请、审核并接受，未预置新关系。仅配对时消费者明确显示好友尚未允许 AI。Provider 在页面启用分享，再单独授权新好友使用 local-small；旧好友的权限保持未允许。
2. 消费者从已完成的本机文章会话打开模型选择。列表分别标明 This node / Friend、不同接收方、状态和价格。此时自己的模型未启动，历史可读。
3. 首次选择好友时，确认框说明原会话留在原服务、现有草稿只复制到新编辑器等待审核。取消后双方订单数和会话数均未增加。随后在页面清空该合成测试草稿，再选择好友模型。
4. 确认后创建新会话 `252332ed-b325-4998-9837-5b585bd6b3f3`，消息、上下文和草稿均为空，双方尚无新增订单。
5. 输入独立算术问题，发送审核明确显示好友身份、没有文章材料。真实好友模型回答 `15`，消费者新增一笔任务，Provider 新增一笔对应任务；结算与收入各一次 0.001 DEV_TASK_BALANCE。这是测试开发额度，不是真实货币。
6. 返回本机原文章会话，原 Provider、回答 `Three` 和来源入口都保留。比较两端所有原有会话的完整摘要，切换、远端问答和随后重启均未改变它们。

## 运行中取消

先前人工操作没赶上生成窗口，本轮改为生产 Owner API 自动观察实际 Provider 订单，未放慢、替换或伪造模型结果。

- 正常创建会话、预览并发单后，08:43:19.863 UTC 观察 Provider 为 running，立即调用原 Ask run 的取消接口。
- 取消响应仍为 running、cancel_requested=true；没有提前宣告计算停止。最终原任务和 Provider 订单均为 cancelled。
- 消费者仅一笔 hold、一笔 release；没有 settle，Provider 没有对应 earning。重复提交同一审核请求仍返回原任务，历史只有一问一答，Provider 对应订单仅一条。
- 随后在浏览器打开该真实任务，页面说明取消已记录，但不能确认 Provider 立即停止计算。

此处取消动作由 Owner API 触发，浏览器验证的是最终提示。不是生成中点击浏览器取消按钮的证据，也不证明 GPU 可立即停算。

## 运行中消费者异常退出

- 第二个独立真实任务在 Provider 确认为 running 后，仅终止专用消费者 PID 60112；Provider 进程保持运行。端口检查确认消费者停止、Provider 仍在线。
- 消费者以相同 home 重启为 PID 24128，原任务恢复为 failed / consumer_restarted_before_completion，没有自动新建请求。
- Provider 仍完成了该原任务，这是远端计算可能继续的实际例子；消费者预留额度释放，未结算，Provider 没有该任务收入。
- 重复提交原审核请求返回原失败任务，Provider 对应订单仍一条。浏览器显示“原订单恢复为失败，没有再次提交”；点击 Check original task 后显示原 failed 状态，没有新增订单或余额事件。
