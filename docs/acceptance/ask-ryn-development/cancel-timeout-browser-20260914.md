## 范围说明

先尝试真实 CPU 模型：观察到 Provider 任务 running，但读取浏览器停止按钮时生成已经完成，因此没有点击停止、没有发送取消请求。这笔任务正常结算；不计作浏览器取消验收。

后续使用已通过产品表单配置的合成 HTTP 服务。取消场景真实延迟 45 秒，超时场景真实延迟 125 秒；不改产品默认 120 秒超时，不伪造取消或超时响应。所有任务由浏览器创建、审核接收方后发送。它验证的是真实浏览器、HTTP、任务和存储流程，不是 GPU 停算或跨公网验收。

## 实际流程

| 操作 | 结果 |
|---|---|
| 浏览器提交取消测试请求，读取节点订单和延迟服务状态 | 原任务 running，生成请求已经到达服务，服务仍在等待 |
| 点击 Stop generating | 页面先显示取消已请求、Provider 可能仍在计算，节点继续核对原任务；没有立即声称计算停止 |
| 延迟服务完成 45 秒等待 | 原任务最终 cancelled；页面说明取消已记录，但不确认 Provider 立即停止计算。后续状态观察时等待已经结束，不把该检查点当作中间 running 证据 |
| 点击 Check original task | 返回原 cancelled，没有新订单、没有新 HTTP 推理请求 |
| 浏览器提交另一个请求，服务真实等待 125 秒 | 默认 120 秒超时实际生效，Provider 从 running 到 timed_out 用时 **120.140248 秒**；错误码 inference_timeout |
| 超时期间持续读取节点状态 | 42 次采样中状态接口最大延迟 16 毫秒；这些采样证明节点仍能处理请求，不代表整机性能基准 |
| 第 125 秒尝试返回迟到响应 | socket 写入失败；原任务保持 timed_out，页面显示原任务超时且没有重新提交 |
| 节点重启、浏览器重新加载，分别核对取消和超时任务 | 原任务 ID、会话消息摘要、状态及额度事件全部不变，未自动发新任务 |
| 恢复正常响应，用户重新输入并审核发送 | 新任务成功；原取消和超时记录仍保留 |

合成服务会话：`a4dc83fb-4695-407d-a36c-0fbd7ec99a88`。三笔新增任务分别为 cancelled、timed_out、succeeded，恰好对应三次新 HTTP 推理调用。原会话 `f64fd70a-974b-43f9-a6d1-64cc5eff4468` 的全部记录保持不变。

取消及超时任务各有一次 hold/release，恢复任务一次 hold/settle。**本轮合成服务属于本机自用，额度均为零**；不能由此声称验证了非零费用超时结算。非零额度的取消、连接失败和重启恢复另见真实双节点记录。
