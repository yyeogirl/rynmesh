# 两个空节点的浏览器首次分享验收 · 2026-09-14

范围：Windows、本机 loopback、生产 Web 构建、两个独立节点和真实加密邮箱进程。无预置邀请、关系、消息、卡片、阅读历史或回执；双方均未配置模型。合成文章由独立 HTTP 监听器提供，仅作为测试输入。不是打包安装、LAN 或跨公网验收。

## 实际页面操作与结果

| 操作 | 观察与核对 |
|---|---|
| A 创建并复制邀请 | 页面包含安装地址、粘贴步骤、一次性/15 分钟有效期和本机地址范围；二维码生成。未实际执行安装包安装 |
| A 停止，B 粘贴并审核邀请 | 界面显示身份、地址和三项分享权限。确认前 B 的受观察好友出站请求为零、关系为零；该观察不覆盖系统所有网络流量 |
| B 确认接受，A 仍离线 | 明确显示无法联系好友，保留原邀请可重试，没有成功提示 |
| A 恢复，B 重试同一邀请 | 双方各一条相同关系；仅消息、小附件、内容卡片权限，无 AI 授权 |
| 双方从好友页发送文本 | 同一消息 ID 和内容摘要在两端一致；接收端显示 Received，发送端收到确认后显示 Delivered |
| A 添加文章源、打开、收藏并分享给 B | B 先收到元数据；主动下载前 B 文档数为 0，A 私有正文获取次数为 0 |
| B 点击 Download and read | B 文档数变为 1，完整性校验为真，页面正常显示两段正文 |
| B 将自己的已保存副本分享给 A，A 主动下载 | 两端接收副本的正文摘要相同，均完成校验和页面阅读 |
| B 停止，A 发消息 | A 显示 In encrypted mailbox · waiting for confirmation，未显示已送达 |
| A 停止，B 恢复 | B 从真实邮箱收到该消息，页面显示 Received；发送方此时不可连接 |
| A 恢复 | 获得回执后显示 Delivered；两端均为三个不同消息 ID，没有重复消息 |
| B 再次停止，A 确认移除好友 | 确认框说明新请求立即禁止、远端可能稍后获知、已保存副本不能收回；页面显示本地已移除、等待通知 |
| 旧凭证访问私有正文 | 以正常配对产生的原凭证执行实际 HTTP 探测：撤销前 200、撤销后 403、A 重启后仍 403；凭证和响应正文未写入证据 |
| B 恢复 | 收到撤销后不再展示活跃好友；B 点击 Read saved copy 仍可阅读自己的正文，两端已保存正文摘要未改变 |

邀请创建到接受约 209 秒，包含主动停机、失败重试和测试观察器重启，不能作为正常安装性能结果。接受到第一条消息创建约 13.6 秒；两端确认状态另见检查点，未测精确网络送达延迟。

## 发现并修复

节点停机时好友列表和内容列表提示加载失败，恢复后数据已刷新，旧错误仍残留。现在将加载错误与用户操作错误分别保存，成功轮询清除加载错误；未确认的发送失败仍保留重试入口。好友会话采用相同处理。

生产构建实际重跑断线恢复后，旧列表错误自动消失。新增两个回归用例覆盖列表恢复、消息恢复，以及后台刷新不能抹掉未确认发送的错误。

测试源最初与节点共用请求服务，触发同步抓取等待自身响应超时。已改为独立 HTTP 监听器后重试成功；该次属于验收环境问题，不计作产品缺陷或通过证据。
