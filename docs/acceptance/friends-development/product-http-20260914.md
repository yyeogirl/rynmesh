# 从空节点开始的首次分享 HTTP 验收

日期：2026-09-14。环境：Windows、Python 3.12、真实节点进程和 HTTP Registry。
范围是本机 TCP 产品接口，不是桌面安装、浏览器操作或跨公网验收。

## 执行方式

```text
python scripts/friend_product_e2e.py --work-root <新的专用目录> --output <新的结果文件>
```

脚本拒绝覆盖已有目录和结果，退出时停止自己启动的进程。双方从空目录启动，
第三个空节点仅参与并发接受竞争。邀请、好友、消息、卡片、正文缓存和送达回执
均通过真实产品路径产生，没有预置关系或卡片。

文章来自确定性的本机 HTTP RSS 服务：通过添加来源、刷新、打开正文、记录阅读和
收藏后再分享。不是把模拟页面当作真实公共来源，也没有直接写入节点缓存。
邮箱使用独立 Registry 进程的 HTTP 接口，消息内容与邀请秘密不写入结果文件。

## 已执行的路径

| 路径 | 检查结果与边界 |
|---|---|
| 邀请取消与本地审核 | 取消后明确拒绝；邀请者进程停止时仍可在接收端审核身份及三项分享权限。未访问审核端点的断言另由现有路由测试覆盖 |
| 并发接受与重复请求 | 两个接收者竞争同一邀请，只有一个成功；另一方得到 invite_used。同一成功请求重试返回原关系 |
| 双向文本与附件 | 实际接收内容一致；相同消息身份重复发送只有一条；发送端只有取得确认才标记 delivered |
| 阅读至卡片分享 | 接收卡片时没有下载文档；主动获取后正文一致、摘要验证通过。重复分享不增加卡片，接收者可将已保存正文分享回来 |
| 离线邮箱与重启 | 接收者停机时显示 mailbox 且 delivered=false；发送者重启保持待确认。再停止发送者，让接收者独立从 HTTP 邮箱获取，随后发送者恢复并取得回执，重复发送仍只有一条 |
| 离线撤销 | 本地立即撤销，远端通知 pending；旧凭证不能获取新的私有正文，重启不恢复权限；接收方已经保存的副本仍可读 |
| 实际时间过期 | 使用真实的一分钟邀请，不修改时钟；到期后接受得到 invite_expired |

## 验收发现的缺陷与修复

旧私有正文路由只捕获 ValueError/OSError，鉴权抛出的 FriendError 属于 RuntimeError，
因此旧凭证虽被拒绝，却产生未处理异常及 HTTP 500。接收端只看到通用获取失败，
先前较粗的“获取未成功”检查没有区分这一问题。

新增检查使用正常配对得到的凭证，对已获取卡片做一次成功对照，再在撤销及重启后
请求尚未获取的卡片。这里只读取本次隔离节点已经生成的关系秘密以签署探测请求，
不建立关系、不注入凭证、不记录秘密或正文响应。

修复是在路由中捕获 FriendError，统一返回 403 / friend_request_rejected。
新增回归用例在旧代码上明确得到 500；修复后 4 项好友路由测试通过。

执行记录按顺序保留：

- [b](product-http-20260914-b.json)：原接口流程通过，尚未加入旧凭证的直接访问检查，不作为该边界的通过证明。
- [c](product-http-20260914-c.json)：加入检查后，在撤销处发现上述真实路由异常，结果为失败。
- [d](product-http-20260914-d.json)：修复后的完整执行，包含撤销前 200、撤销后 403、进程重启后 403。

6 项通过。修改后重跑受影响的 4 项路由测试及完整 HTTP 流程，Ruff 通过。
