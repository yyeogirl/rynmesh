## 已实现的来源事务

`ask_ryn/privacy.py::ConversationPrivacy` 是内部步骤，尚未连接设置页或新的 HTTP 路由。它不启用会话同步，也不执行网络请求。

- 审核令牌绑定当前来源快照，包括会话、未发送草稿、冲突/恢复项和任务记录。审核后出现新内容时拒绝旧操作。
- 原任务处于排队、发送、运行或未知状态时先等待确认；此步骤不执行 GPU 取消、不改变订单结算。
- 同一原子提交清除普通会话、独立恢复副本、本机草稿、同步候选和已结束任务的正文。保留删除标记、迁移摘要及任务身份/请求指纹，阻止旧浏览器导入、旧设备投递或同一请求重试重新生成内容。
- 清除凭据保存在加密来源文件中。响应丢失或重启后重试返回原凭据，后来新建的会话和草稿保持不变。
- 只处理已知来源数据范围；顶层未知扩展保持原样，未来版本不覆盖。返回值明确为 `conversation_source`，远端确认固定为否。

好友关系 `state.json` 是受私有文件权限保护的 JSON，不能将其描述为加密会话容器。其历史 `secrets.json` 及迁移备份也属于需要明确处理的凭证范围。

复用接口时还有两个已经核对的差别：

- 旧浏览器库实际为 IndexedDB `ryn-private-ai-chat`，包含 `keys` 和 `conversations`。当前 `deleteConversation`/`clearConversations` 捕获并忽略存储错误，不能直接作为已成功擦除的凭据；完整维护入口需要返回真实事务完成结果，并清除当前会话内存。节点导入后仍保留这些旧浏览器恢复副本。
- `TaskOrderStore.purge_encrypted_response` 能保留订单身份并删除持久化加密结果；`ConsumerCommands.acknowledge` 当前只移除标记为 ephemeral 的内存结果。完整清理须协调这两个范围及正在执行的后台任务，不能把 acknowledge 当成完整订单结果清除。

## 下一步协调流程

1. 在 Owner 设置入口显示导出/清除范围、数量及保留项，不默认导出密钥、邀请能力或 Provider 凭证。
2. 以一个稳定操作身份保存审核结果和分步进度。来源提交、副本清理、备份处理、索引和浏览器确认分别记录；部分失败保留重试入口，已完成步骤不重复清除新内容。
3. 遵守设备配对 → 来源 → 副本的现有锁顺序；索引重建和网络调用不得放在来源锁内，避免和读取来源的后台任务互相等待。
4. 验证端到端流程：审核后编辑、取消、磁盘失败、重启、旧消息、离线/移除设备、清除后再次使用。只有本地范围全部完成才显示本地完成；远端须另有真实确认。

## 节点清理协调接口

后续实现已接入完整节点的 Owner API，位于 `/api/local/privacy/conversations`：审核、创建清理操作、查看/继续进度、取消尚未提交的操作，以及重新审核发生变化的剩余备份。设置页尚未接入，以下为节点接口验证。

- 同步副本中独有的旧会话 ID 也列入审核。擦除不自动开启同步；以后启用时仍转换成永久删除标记，旧投递不能进入恢复区。
- 只删除来源 `.migrated` 和来源、同步副本、搜索索引的已审核原子临时文件。名称、位置、SHA256 都需匹配；其间新产生的副本不会被自动纳入。删除期间使用与索引、来源写入一致的锁顺序，避免清除仍在写入的文件。规范来源、阅读元数据与规范索引文件不作整目录删除。
- 备份内容变化时停止，重新审核当前剩余版本才继续。来源提交前失败的操作可取消，再生成新审核；已提交来源的操作不能冒充可撤销。
- 订单适配器同时清理已保存的加密结果和内存结果。磁盘终态不够：后台仍处于排队/执行/未知状态时继续等待。保留任务身份、状态与结算元数据；真实消费服务测试中余额保持一致、同一请求未再次派发。
