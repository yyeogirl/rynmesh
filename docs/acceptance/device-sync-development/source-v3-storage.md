# 阅读来源 v3 的兼容与持久化边界

本次变更解决万条来源中的重复保存、读取与校验；不改变线上同步消息格式、身份、因果顺序或回执含义。

## 存储格式

| 格式 | 读取 | 后续写入 |
|---|---|---|
| 原未启用同步的阅读文件 | 保持原有兼容行为 | 用户启用范围后先保存原始 `.migrated` 备份 |
| `ryn.consumption.v2` | 完整校验，在内存中读取 | 首次重写前保存原字节至 `.v2.migrated`，再原子保存 v3 |
| `ryn.consumption.v3` | 解释明确的投影标记后校验 | 继续原子保存 v3 |
| 其他命名版本 | 拒绝 | 原文件保留 |

v3 中，某个实体的 `projected` 为字符串 `record`，仅表示其已应用值与**该实体自己的**完整 `record` 相同。它不能引用其他实体。不同的并发投影仍保存完整对象；未知标记或无效记录被拒绝。v2 不接受该标记。

完整对象在验证规范 JSON 相同后才共享内存身份；普通因果写入/合并也只在已应用值等于当前值时共享。保留未修改的实体扩展字段、来源扩展字段和文件扩展字段。同步导出仍只包含完整的 `scope`、`id`、`record`，不会把存储标记传给其他节点。

v3 持久化省略 JSON 空白、不额外排序对象键；读取按 JSON 语义处理。导出仍按实体键排序，网络签名和指纹仍使用规范 JSON。旧文件备份保持原始字节，不按新格式重写。旧版本程序不能读取 v3，降级时不得直接覆盖新文件。

## 事务与验证

- 本地阅读变更与因果状态仍在同一次原子写入中保存，保留 fsync 和现有大小限制。
- 来源导入与待同步批次计算，或来源导入与回执核对，合并为一次副本事务。写入失败不返回批次或确认；旧回执仍按最新来源值判断过期。
- 状态中的待处理数与冲突数取自同一份已验证来源快照，不重复读取另一份来源计算冲突。
- 已授权的传输操作把范围启用检查与来源读取合并；普通内部桥接默认不会自动启用范围。配对策略检查仍先于来源操作。
- 实体键缓存最多 30000 个已验证的范围/标识哈希，不存正文或记录值。每次输入仍先验证类型与标识；文件、内容、身份与权限不会因缓存而跳过检查。
- 规范 JSON 编码仅复用编码选项，不复用内容或输出。兼容测试对照原编码的 UTF-8 字节，覆盖 Unicode、数字表示、并发调用及循环/非法输入后的恢复。

测试覆盖原始备份、备份失败、写入失败、未知字段、旧版本中非法标记、无效内容、并发位置、重启恢复，以及在同一次接收中启用新范围不覆盖原 v2 备份。最终耗时及完整回归结果记录在本目录 README，不能用本格式说明代替验收结果。

## 增量测量的复用边界

验收脚本可复制一次实际 TCP 同步后保留的两个合成节点目录，重新绑定它们原来的回环端口，核对双端配对、来源数量、实际收藏集合、来源记录及已有回执，再开始 100 次普通变更。脚本不制造回执，也不改原始基线目录；旧节点必须已经停止，否则端口绑定应失败。

这种方式避免每次优化都重做同一份初始合并，但不产生新版的首次合并证据。最终还需从全新目录执行完整路径，并保留两类测量的区别。取消收藏后，其因果实体仍计入元数据总量，普通阅读列表不必继续显示没有阅读历史的取消项；脚本分别验证实体总数和实际收藏集合。
