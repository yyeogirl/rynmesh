# 阅读数据协调清理开发验收

2026-09-11，开发分支候选。本记录补充 G08/SYNC13，不代表完整产品验收通过。

## 用户行为

Settings → Privacy & data → Reading data：审核本地阅读、收藏、进度、同步来源/副本及已知备份数量后确认。页面显示来源、同步副本、备份、搜索四个步骤。文件占用或索引忙碌时保留进度，重启后继续原操作；变化备份必须重新审核。仅来源尚未提交的操作可以取消。

旧的 live “Clear history”按钮由新面板替代，来源清理后刷新顶部阅读条数。确认弹窗关闭时保留操作已聚焦的状态/错误提示，避免跳回设置页顶部。

## 存储和重试边界

- 阅读来源使用 `ryn.consumption.v4`，只在执行此清理时升级；普通 v2/v3 路径沿用已有迁移。首次升级保留精确原字节的 `.migrated`、`.v2.migrated` 或 `.v3.migrated`，这些即将产生的备份也纳入审核。
- v4 的 `sync` 可以为 null。`privacy_erasure` 保存版本、设备身份、审核凭据和无正文的因果删除记录，不自动开启任何同步范围。以后主动开启某个范围时先恢复已知删除时序，再记录清理后新增的收藏或阅读。
- 清理观察当前来源、旧投影及已知副本的记录。已审核的旧快照无法恢复已清除值；同一内容可以再次主动收藏或打开。未观察到的远端并发编辑仍可形成需明确处理的冲突，不推断远端擦除成功。
- 加密进度文件 `privacy/reading-cleanup.json` 只保留当前或最近一次操作，4 MiB 上限；单调递增序号防止旧审核被重新执行。来源已提交、进度写入失败时，可从来源凭据恢复，避免清除期间产生的新工作。
- 协调锁顺序为索引写锁/文件锁 → 配对 → 来源 → 副本；索引重建在释放这些锁后执行。操作不新增后台线程或定时器，复用节点现有存储、锁和搜索服务。
- 仅删除名称、位置与审核 SHA256/大小匹配的已知备份和原子遗留文件。新出现的文件不自动纳入；变化文件重新审核后才继续。
- 本次范围不含已保存文档、离线正文/图片、原文缓存、浏览器副本、其他设备或用户自行备份。来源头部的未知扩展字段保留；同步因果记录也不承诺从物理介质上不可恢复。
- 来源沿用 256 MiB 上限，最多 20000 个同步实体；最大长度 UTF-8 ID、64 个 actor、最大计数的两份删除记录合计上界 266820000 字节，另留 1 MiB 给本功能头部后仍低于上限。额外未知扩展可能触发容量拒绝；失败保留原来源，不能删防重放记录绕过限制。v4 万条数据性能尚未复测。

v4 规模续验见 [source-v4-scale.md](source-v4-scale.md)：首次删除传输错误及恢复后 61.130 秒超标记录保留；减少相同凭据的重复验证后，万条基线的 100 次重新收藏和双端确认复测为 56.831 秒。A 为 v4、B 为 v3，本机恢复增量结果不替代完整平台验收。

## 复现方式

使用 `scripts/accept_offline_reading_node.py` 的专用新目录 `rynmesh-offline-acceptance-reading-cleanup`、节点端口 18880、合成来源端口 18881。从实际设置页面审核、取消和确认第一轮。

通过本机 consumption API 新建合成收藏，再复制当前 `consumption.json` 到 `.consumption.json.aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa.tmp`，使用 `scripts/hold_acceptance_download.py --reading-orphan aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa` 持有该文件。第二轮页面确认会停在备份步骤。停止并以 `--reuse --source` 重启同一节点，新建同 ID 收藏；通过显式 ReadWrite 分享的文件句柄改变合成备份，验证重新审核。释放持有句柄，点击继续，然后在 My reading 的 Saved content 找回新收藏。

最后执行 `scripts/accept_reading_cleanup_result.py --home <专用合成目录>` 生成 HTTP 证据。脚本拒绝其他目录或尚未完成的任务。验收节点、标签页和文件句柄均已关闭，合成数据目录保留。
