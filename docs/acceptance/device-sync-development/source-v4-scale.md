## 本次场景

从上次真实 TCP 同步完成的合成万条基线复制到新的独立目录，核对两端已确认状态、收藏集合和完整因果记录一致。没有构造同步回执，也没有改写原基线。

A 通过生产 `ReadingCleanup.preview/begin` 清理阅读数据，实际升级到 `ryn.consumption.v4`，保留阻止旧数据复活的删除记录。清理协调使用真实来源、副本、备份和空搜索索引；搜索内容规模不在本次范围内。随后通过真实加密 TCP 批次确认删除，检查两端各保留全部因果实体、收藏均已清除。B 保持 v3，验证版本之间可同步。

在删除确认完成后，A 通过正常来源 API 重新收藏 100 个相同内容标识，分别记录来源写入、传输、双端确认和加密 JSON 字节数。60 秒参考目标只用于这 100 次变更，清理和整批删除确认单独计时。操作直接调用正式传输逻辑，未包含后台调度等待。

## 校验开销修复

同一份 `privacy_erasure` 删除凭据在普通收藏写入间不变，原实现每次读取都重新遍历验证全部记录。来源现在只缓存最近一次完整验证成功的 SHA-256 内容摘要。每次读取仍重新读取文件并计算整份凭据的规范摘要；内容不同必须重新验证。缓存不保存正文、不修改磁盘格式、不使用文件时间或大小判断相同，实例重启后重新验证。

新增 5 类篡改测试：预热来源并重新收藏后，改变凭据版本、actor、因果时钟、删除值或结果标志，并将文件时间恢复成旧值；原实例和重启后的实例均拒绝读取及继续写入，损坏文件保持原样。阅读来源与协调清理专项 32 passed。

[优化后复测](scale-v4-10000-cached.json)从同一失败目录重新复制并恢复 5000 条确认，随后执行相同的 100 次重新收藏：
