# 搜索与找回开发验证

日期：2026-09-11。检索核心、四类本地数据、Owner HTTP 接口及统一页面已接入；完整产品验收尚未完成。

## 已实现

- 本地关键词匹配：空白分隔的关键词取交集；中文无空格词组直接匹配，英文不区分大小写。标题匹配优先，也可按时间排序。
- 支持类型、来源、好友及时间范围筛选；默认每页 20 条。内容身份由数据适配器提供，相同文本的不同消息保留独立结果。
- 匹配片段返回纯文本和 Unicode 码点范围，页面应按码点切片高亮，不能当 HTML 渲染。
- 查询时重新读取授权数据，核对与索引记录的指纹。删除、撤销或修改后的旧正文不返回；索引尚未更新时标记部分结果。数据源读取失败时返回固定错误码。
- 索引按节点密钥加密，使用已有原子存储和文件事务。缓存损坏可从原数据重建；未知版本拒绝覆盖；未知扩展字段保留。
- 重建状态可查询，同时只允许一个重建。分页签名绑定查询、筛选和结果版本，发生变化要求刷新，避免静默重复或跳过记录。
- 每个索引最多 10 万条、64 MiB 明文；倒排表超过计数限制时回退为完整候选扫描，避免无限增加内存。超出数据上限明确失败，不修改原数据。
- 从真实消费记录、阅读缓存、校验后的私有文档、好友卡片/聊天和加密 Ask 历史构建索引。搜索不触发获取或提取；过期但仍存在的阅读缓存可用于本地搜索。原生已保存文本会核对签名清单及文件哈希后使用。
- 相同来源 URL 和文件哈希合并收藏、历史和分享标签；同一 URL 的不同修订保留独立记录。未获取的卡片不索引远程正文，已有提取截断标记继续展示。
- `local-search.index` 由共享注册表管理，首次延迟 1 秒、每轮完成后间隔 1 秒。接口复用 Owner 鉴权；关键词使用 POST 正文，不写入请求 URL。
- 导航栏新增 Search。支持过滤、纯文本高亮、加载更多、重建与失败恢复；关键词和筛选存在浏览器导航状态中，返回时重读结果并恢复位置。打开正文再检查权限和当前数据，复用阅读器及阅读进度；好友消息、卡片和 Ask 消息有精确定位入口。

## 浏览器与本地节点

[Windows 浏览器记录](windows-browser-node.json) 使用真实节点进程和实际 HTTP/页面，四类记录使用合成种子写入真实存储。种子配对使用测试用内存传输，不作为跨进程配对或公网验收。

已实测：四类查询各返回正确结果；中文/英文混合查询找到收藏及历史的同一条文章；没有模型仍能打开旧缓存正文；返回保留关键词；Ask 与好友消息结果打开后，命中消息获得焦点。查询记录只保存数量、类型、标识、耗时和正文哈希。验收节点与页面关闭后确认端口释放。

## 万条真实存储与恢复复测

数据为 1000 条同时收藏和读过的文章、500 张好友卡片、500 条好友消息和 8000 条 Ask 消息，均写入真实节点存储；好友关系为本机合成种子，不代表真实配对验收。参考机器 Windows 11、i7-9700K（8 核/8 线程）、32 GiB 内存、Python 3.12.10，无模型参与搜索。

- [首次测量](real-store-scale.json)：冷建 2.072 秒，20 次 Owner ASGI HTTP 查询 p95 1.594 秒；发现周期检查将已就绪索引误报为部分结果（6/20）。
- [修复后测量](real-store-scale-current.json)：p95 1.336 秒，部分结果误报 0/20，强制重建 1.799 秒；完整分页 10000 条、唯一身份 10000，无重复遗漏。这些是真实存储与 ASGI HTTP 耗时，不包含 TCP 或浏览器绘制。
- 普通无变化检查保留 ready 状态；用户手动重建则确实重新生成索引。实际数据变化仍显示索引中，旧片段继续经过当前数据核对。
- [进程恢复](process-recovery.json)：损坏索引缓存，重建期间终止实际子进程；新节点工作器自动恢复，耗时 2.809 秒、恢复 10000 条。1004 个原始数据文件哈希全部保持。仅模拟进程中断，没有模拟整机断电。
- [浏览器分页](browser-pagination.json)：加载 40 条，打开第二页本地正文再返回，40 条及关键词保留。滚动恢复改用应用实际的 `.app-main` 容器，组件测试验证 1600px 恢复；浏览器未测量精确像素。
- 分页检测到数据变化或请求失败后清除旧片段，提供刷新入口，避免继续展示已失效结果。
- [原更新测量](tcp-change-before-scheduling.json)：新增 2.306 秒，改名 6.930 秒，超过建议 5 秒；记录保留。删除和改名前的旧片段均在首次查询隐藏，删除后直接打开返回 409。
- 将检查间隔从 3 秒缩为 1 秒后，[首次 TCP 复测](tcp-change-recovery.json)新增 4.095 秒、改名 4.108 秒。计时包括提交返回后的查询等待，改名计时也包括旧标题验证。缩短间隔会增加空闲扫描频率，仍由单个共享工作器串行执行。
- [当前 TCP 复测](tcp-current.json)：20 次查询 p95 1.627 秒、部分结果误报 0/20；新增 2.326 秒、改名 4.827 秒。删除后的首次查询不再命中，直接打开返回 `search_result_unavailable`。两次复测均达到参考机器建议时限，不能据此承诺所有机器和负载下的硬性时限。

可复现命令（选择专用合成数据目录，禁止使用个人节点目录）：

```powershell
python scripts/accept_local_search.py --home <new-dedicated-home> --output <scale-result.json> --serve
python scripts/accept_local_search_changes.py --port 18852 --output <tcp-result.json>
```

已有专用规模目录可在第一条添加 `--reuse`；目录名须以 `rynmesh-search-scale-` 开头。恢复脚本 `scripts/accept_local_search_recovery.py` 使用相同专用目录，须先停止该验收节点。所有证据只含合成身份、数量、哈希、状态和耗时。

本轮全后端 1067 passed / 29 skipped（5 条警告）；前端 Search 专项 8 passed，TypeScript 与生产构建通过。此前前端全量为 102 passed，本轮新增两项专项没有据此推算全量通过数。构建仍提示主 chunk 超过 500 kB。工作器间隔调整后，索引、真实数据源及共享调度专项 45 passed / 1 deselected，Ruff 通过。验收节点和页面已关闭，监听端口释放。
