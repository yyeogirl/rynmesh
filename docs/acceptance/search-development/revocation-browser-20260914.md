# 好友撤权与搜索联动

2026-09-14，候选 `a44f578`，Windows Chrome、两个已有独立 loopback 节点。复用先前通过页面建立的 A/C 关系和两条附件消息，不重做邀请或性能验收。本轮无产品代码修改。

## 实际操作与结果

1. 恢复 A/C，确认原关系有效。A 从 For You 的 Read later 入口保存合成文章、打开正文，再通过分享弹窗选择 C。页面显示对方已收到卡片。
2. C 搜索两条既有附件消息可得到两个独立结果。搜索文章标题只得到一张元数据卡片，正文专用词无匹配；未下载内容没有被冒充为已全文检索。
3. C 从搜索的 Open share 定位到卡片，主动选择 Download and read。页面正常阅读；正文搜索得到一个结果，包含 Reading history、Saved、Friend shares 三种来源，按 A 筛选也能找到该结果。
4. 通过 Windows 文件句柄阻止替换 C 的加密索引文件，保留撤权前的旧索引。没有改写原始消息、关系或正文，也没有在搜索实现中跳过鉴权。
5. A 页面确认移除 C。撤权通过真实节点 HTTP 到达 C。随后查询两条受保护消息为零，按 A 筛选正文也为零；两条消息直接打开均为 **200→409**。C 的旧索引文件 SHA256 与撤权前完全相同，证明结果不是依靠索引已经删除旧条目才安全。
6. C 页面 Refresh results 后清除旧片段，显示零条及索引未完成提示。此时保存副本的来源标签发生变化，索引一致性检查暂不返回该结果；直接打开副本仍为 **200**，正文摘要保持一致。未把这一暂时空结果当作副本已被删除。
7. 释放索引锁，后台自动恢复为 ready、仅一条记录。C 去除好友筛选后找到自己的副本，标签只剩 Saved、Reading history；原 Open share 搜索入口消失。旧好友筛选仍不返回该副本。
8. 关闭 A 及其文章来源，重启 C 并重新加载正文页面，仍读到保存正文。再次通过 HTTP 核对旧消息为 409、结果为零，自己的副本摘要不变。
9. 使用撤权前的消息链接打开 C 页面，显示好友不可用或访问已移除，消息没有显示；已保存文章仍提供 Read saved copy。该页面未记录浏览器 warning/error。

## 证据与复现

- [HTTP 检查点](revocation-checkpoints-20260914.json)只记录身份、数量、状态、标签和摘要，不保存正文、关键词、邀请秘密或凭证。
- `scripts/observe_search_revocation.py` 为只读观察器；`verify` 检查旧索引摘要一致、两条受保护结果拒绝、独立副本归属及重启不变。
- `scripts/accept_reading_write_lock.py` 仅新增受限的专用 C 节点索引锁目标，用于复现旧索引滞留；停止该辅助进程释放故障。
- 原始配对与附件证据继续有效，但专用 A/C 夹具现在已撤销关系；后续工作必须先检查当前状态。没有重新建立关系或覆盖旧验收记录。
- 观察器验证、Ruff 和差异检查通过。产品实现未改变，未重跑已有单元测试和万条性能测试。

范围限制：未测量跨公网撤权延迟；不能要求离线接收方在收到撤销前就知道权限变化。此次为在线 loopback 通知与接收后检查，不是打包桌面、真实多机或完整隐私验收。所有新增页面与验收节点已在本轮结束时关闭。
