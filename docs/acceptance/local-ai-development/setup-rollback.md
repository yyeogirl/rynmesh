# 安装取消后的配置恢复

日期：2026-09-12。分支：`codex/user-product-development`。对应 AI03、AI04。

## 用户行为

取消只表示已请求停止。安装步骤结束前保持“正在取消”，迟到的下载进度不能改回“运行中”。恢复结束后分别显示：

| 结果 | 行为 |
|---|---|
| 旧配置恢复且健康检查通过 | 显示配置已恢复、健康检查通过；取消任务结束 |
| 配置恢复，但旧模型不能启动或健康检查失败 | 显示模型不可用，提示检查本地服务并重试 |
| 恢复文件失败 | 显示恢复失败，保留原始恢复副本；“Retry configuration”先重试恢复，再开始新的配置 |
| 首次安装，没有旧配置 | 明确说明无需恢复旧配置，不能声称恢复了不存在的模型 |
| 节点重启后恢复文件成功 | 显示文件已恢复、模型状态待核对；不宣称模型已就绪 |

配置或恢复进行中，普通服务查找不会发布未完成的配置。同步与异步配置入口互斥，避免另一安装覆盖当前恢复副本。成功切换及恢复时重新构造服务适配器，避免同一清单路径继续使用旧缓存。

## 持久格式与边界

新文件 `llm/setup-recovery.json` 使用严格整数版本 1。开始异步安装前，以共享原子存储写入旧服务清单和 Provider 设置的原始字节，保留未知扩展；编码和 SHA-256 用于完整性校验。该副本含私密配置，使用共享存储的私有权限，内容不进入任务状态和错误消息。

每个源配置文件最多 2 MiB，恢复记录最多 6 MiB。超过限制或无法保存原配置时，安装不会开始。恢复前验证完整记录；不支持的版本、未知记录字段和摘要错误都拒绝恢复，原文件保持不变。源配置的未知字段作为原始字节保存，不会因恢复被丢弃。

写入失败保留原恢复记录。写入完成后，先原子替换为不含配置的 `committed` 记录，再尝试移除；残留的完成记录不能恢复过时的配置。节点重新创建路由时先处理未完成恢复，不自动启动模型；原版本 `setup-job.json` 的中断任务恢复继续支持。

模型下载、模型文件与会话不在该恢复副本中；本次不增加模型自动删除。原生启动如需更新运行时凭据，仍由既有生命周期模块处理。

## 实际验证

`tests/test_setup_recovery.py` 使用真实临时配置文件、真实回环 HTTP 模型健康接口及异步安装路由。安装过程由可控替身模拟写入后取消；因此不是一次真实模型安装。

- 成功、健康失败、恢复写入失败三种结果分别验证，接口不返回私密标记或路径。
- 恢复写入失败后，修复故障再通过原应用重试，先恢复原始字节；不会把未完成的替换文件当成新的恢复基线。
- 使用相同数据目录重新创建应用，恢复原清单和设置的精确字节，状态为 `restored_unchecked`。
- 同步安装不能插入异步安装；取消后的迟到进度保持取消状态。
- 非法版本、摘要错误、未知恢复字段、最大容量及完成记录移除失败均有覆盖；完成记录不能回滚后来的新配置。
- 页面组件验证取消提示不保证恢复成功，最终恢复失败时显示可用的重试按钮并提交一次配置请求。

后端恢复专项 9 passed；加入恢复期间服务缓存隔离断言后，最终相关回归 82 passed / 4 skipped（10.15 秒）。页面专项 27 passed。

本轮全量后端 **1419 passed / 29 skipped**（280.36 秒，5 条既有弃用警告）。全量运行开始后补紧了恢复健康检查期间的服务隔离，该最终改动使用上述 82 项相关回归再次验证。前端全量 **219 passed / 42 files**（33.28 秒）；补全测试状态的必填字段后，页面 27 项复测、TypeScript 和生产构建通过。生产 JS 为 `index-CSbHlGG5.js`，638.54 kB，仍有原有大包体积提示。全后端 Ruff、差异检查及 95 条需求清单校验通过，完整验收状态未提升为通过。

完整 macOS 打包应用上的取消、关闭重开、原生模型启动及再次问答仍需按[安装恢复步骤](runtime-install-recovery.md)执行。本记录不能替代这些实机验收。
