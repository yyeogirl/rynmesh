## 修复内容

安装任务保存受限的恢复选项：仅包含托管模式、已明确选择的模型档位、包名和端口。取消、失败和进程重启后保留；不保存来源 URL、文件路径、密钥变量或上次确认。页面首次加载恢复这些选项，随后不覆盖用户编辑。

旧记录、非托管请求及不能可靠恢复的选择不会被猜测为默认本地 API；页面要求用户重新选择安装方式。这里只恢复已有表单，不增加自动下载或新的模型来源。

## 复现工具与边界

- `scripts/accept_ai_recovery_node.py` 启动固定名称的独立目录；重启显式使用 `--resume`，不复用其他用户节点。它加载真实安装实现和生产前端。
- `scripts/observe_ai_recovery.py` 记录该节点的有界元数据，并在已停止下载时计算文件摘要。停止进程前通过 PID、脚本和目录验证了测试进程身份。
- 页面组件和后端用例覆盖模型选择恢复、重新确认、旧记录禁用默认重试，以及私密输入不进入状态文件。

**续验已完成真实模型下载及全文件校验。** 最终文件 491400032 字节，独立计算的 SHA-256 为 `74a4da8c9fdbcd15bd1f6d01d621410d31c6fc00986f5eb687824e7b93d7a9db`，与固定目录记录一致；没有使用旧测试目录中的完整模型替代下载。任务仍使用从 16 MiB 检查点恢复的同一 ID，随后进入真实原生运行时下载，健康检查返回 200，服务尚未被标记就绪。

运行时安装、真实问答及其重启验收仍在继续。Windows 浏览器流程也不替代 macOS 打包桌面应用验收，AI03 保持验收中。

续验时浏览器工具两次返回 `Unable to load browser request-header policy`，没有取得新的页面证据。直接节点检查仍返回 HTTP 200，同一真实下载继续增长；这项工具连接故障没有被写成产品页面失败，也没有使用接口结果替代页面验收。

`scripts/accept_ai_recovery_inference.py` 为此专用目录提供实际 Owner API 的问答核验。仅在安装成功、本机模型就绪且本地调用价格为零时提交；私有测试凭据先保存固定任务身份，脚本重试不会换任务。后续记录只导出状态、计数和摘要，检查重复提交、原服务绑定、进程重启及归档内容一致，不导出模型输入输出。这项 API 核验也不算页面验收。
