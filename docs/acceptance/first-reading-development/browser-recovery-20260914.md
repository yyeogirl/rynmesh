2026-09-14，Windows，本地生产构建与真实 Python 节点。新建空数据目录，采用桌面默认的 14 个公共来源，没有配置模型、好友或预置内容。操作经浏览器页面执行；[API 检查点](browser-checkpoints-20260914.json)只读核对持久结果。此记录不代表打包桌面或完整产品验收通过。

## 修复的真实问题

从 My reading 等普通入口打开文章的 ContentViewer 缺少收藏/取消收藏操作。现在读取现有收藏状态，使用已有消费记录接口保存，只在收到匹配的保存结果后更新按钮；失败明确提示重试。底部按钮允许换行。没有新增数据格式或后端存储。

## 复现设施与验证

- `scripts/accept_first_reading_node.py`：启动隔离节点；重启使用同一目录和 `--resume`。
- `scripts/observe_first_reading.py`：只读观察，输出记录 ID、状态、时间和摘要，不导出文章正文、URL 或个人绝对路径。
- `scripts/accept_reading_source.py`：仅在 loopback 提供独立合成来源；`source-mode.txt` 控制正常/503，产品仍经真实 HTTP 访问。首篇阅读文章来自公共网络，合成来源仅用于故障恢复。
- `scripts/accept_reading_write_lock.py`：只允许专用夹具目录中的两个指定文件，用 Windows 文件句柄禁止原子替换；关闭辅助进程即释放，不更改原文件字节或 ACL。两次故障均已释放。
- 受影响阅读交互：17 项通过；全量前端：231 项通过（43 文件）。两者有重叠，不相加。
- TypeScript、生产构建、三个新 Python 辅助脚本 Ruff 检查通过。构建仍有原有的大包提示；此次没有后端产品修改，未重复全量后端测试。
